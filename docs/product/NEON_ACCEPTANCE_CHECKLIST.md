# 思弈阁 Neon 定稿验收清单

**范围已确认，验收尚未执行。** 本清单整理于 2026-11-24。用户已确认以打磨后的 Neon 版为目标，交付包中的全部功能进入重构范围，按四批交付。赛制、评分和公开范围等仍需明确的规则见[已确认口径](#已确认口径)。现有 [PRD V2](PRD.md#14-可测试验收标准) 和 [V1 验收基线](PRD_V1_BASELINE.md) 继续用于各自版本的验收。

- **体验样板**采用 [Neon 发布页](https://sites.google.com/view/siyige/full-page-embed)，包括导航、页面布局、交互节奏、按钮反馈和状态提示。正式验收时，用同一辩题、立场和示例分别走一遍样板与新版本。
- **本轮核对的文件**来自 `siyige_v2_complete_bundle`。交互参照 `frontend/siyige_debate_studio.html`，范围及反馈参照 `docs/思弈阁_v2.0_全量PRD_ADR决策与取舍清单.txt` 的第一、二、四部分。下文所列样板行为来自交付文档和 HTML 静态核对，发布页与打包版的一致性待浏览器验收时核对。
- **怎么记录** 每行初始为「待验」。执行后填写通过、失败或阻塞，并附受测版本、环境、使用的数据和证据。Fake 是无需付费的替身模型，用于验证流程和失败恢复；真实反驳质量、各供应商接通、麦克风和真实跨用户共享分别验收。各批的未通过项跟随该批验收，修复后用同一用例复测。

## 已确认口径

| 口径 | 已确认规则 |
| --- | --- |
| D1 赛制 | 对外统一为单场四轮制（立论、攻辩、交锋、结辩）与思弈杯四阶晋级（初赛、复赛、半决赛、决赛）。未解锁赛段允许自由选轮练手，仅在当前已解锁的最高赛段胜出时触发下一阶解锁。 |
| D2 复盘与裁决 | 训练与杯赛统一使用 Neon 五维评分。三席中一席失败，可单席重试或按剩余有效席先行出分，复盘可继续。修订重评只给提分参考，原局胜负和 ELO 保持原值。 |
| D3 模型体验 | 气势条与交锋图谱在每轮双方发言结束后同步更新一次。篇幅按目标区间 ±20% 判通过。真实对局失败优先提示重试，若切到演示兜底则标明练习局，该场不计正式 ELO。 |
| D4 积分与杯赛 | 仅完赛且非演示兜底的对局结算一次 ELO，平局记 0。思辨道场每题仅首次答对奖励 +5 ELO。排行榜 ELO 同分时胜率高者在前。 |
| D5 模型配置 | 模型已保存即可在裁判席选用，测试连接为可选校验。密钥仅在服务端加密存储，前端只显示用户自定义别名。 |
| D6 公开边界 | 所有自定义内容与复盘默认私密，用户确认后公开，可随时撤回，撤回后公开直链失效。公开主页只展示昵称、头像、段位、ELO、胜率、最高杯赛阶段和已公开复盘。允许导出公开复盘的 Markdown。 |
| D7 道场计时 | 30 秒为碎片化微训练的参考计时，到时仍可作答。 |

## 第一批验收走法

1. 用两个测试账号，在隔离 MySQL 环境中登录。账号 A 选择一题和一方开始比赛，先用 Fake 走完四轮；生成中上滑、刷新一次，并制造一次回复失败再重试。核对同一场的服务端发言与轮次。
2. 完赛进入复盘，点击双方批注，核对所引用的原句。修改本人一句话并重评，刷新后确认能同时找回改写和原话。再让账号 B 查看账号 A 的私有对局链接，确认读取受限。
3. 打开桌面和窄屏视图，按样板核对导航、四轮进度、滚动、完成提示与示例入口。从历史打开同一场，检查视觉与数据。将首批 NEON-01–11 的结果、受测版本和证据填回表格，按 [TASKS](../planning/TASKS.md) 登记实际交付与风险。
