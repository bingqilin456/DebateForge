## 2. 登录与恢复

`[已确认]` 沿用 V1 的服务器端 Session、登录/注册与跨用户 404 隔离；`[已确认]` 刷新后先确认登录状态，再继续练习。

### 2.1 线框

`[设计建议]` 登录与恢复就地渲染，不占独立路由；未登录时不显示需要会话的入口。

```
┌ 顶栏：思弈阁 · 文字辩论练习 ───────────── 用户名 · 退出登录 ┐
│                                                            │
│  ┌ 登录状态尚未确认 / 正在恢复登录状态 ───────────────┐    │
│  │ 说明当前不能继续操作的原因                          │    │
│  │ [恢复登录状态]                                      │    │
│  └─────────────────────────────────────────────────────┘    │
│  匿名时：登录表单 ⇄ 注册表单                                 │
│  已登录时：主视图导航（开始练习 / 历史 / 设置）              │
└────────────────────────────────────────────────────────────┘
```

### 2.2 状态与恢复

| 状态 | 触发 | 界面表现 | 允许动作 | 禁止 |
| --- | --- | --- | --- | --- |
| 状态未确认 `[已确认]` | 首次挂载、刷新 | 说明文案＋“恢复登录状态”，不渲染业务视图 | 手动恢复登录状态 | 未确认前发请求、提交发言或创建会话 |
| 恢复中 `[已确认]` | 用户点击恢复、自动恢复 | 忙碌提示，相关控件禁用 | 等待本次恢复结束 | 重复触发、并行恢复、把失败当成已登出 |
| 已登录 `[已确认]` | Session 有效 | 显示用户名与主视图导航 | 全部授权操作 | 用旧用户状态渲染他人数据 |
| 登录失效（401）`[已实现]` | 任意受保护请求返回未认证 | 就地提示“登录已结束，请重新登录”，保留当前地址（含 `#debate=`） | 重新登录后回到原会话 | 静默重试、清空页面、丢弃已提交内容的展示 |
| 注册/登录失败 `[已确认]` | 400、401、409、429 | 受控错误文案（输入问题、凭据错误、用户名冲突、过频） | 修改后由用户手动重试 | 显示上游原文、请求头或任何凭据 |

- `[已确认]` 未确认登录状态前不得发请求或创建会话；恢复中不重复触发、不并行恢复。
- `[已实现]` 该约束在客户端以“无 CSRF 令牌即拒绝写请求”落地；恢复失败保留“未确认”状态并给手动入口，不自动转为匿名。
- `[已确认]` 401 属于“权限或登录失效”通用态，统一走本文 [§3](#3-共通状态与恢复) 的恢复动作。
- `[已实现]` 401 时保留当前地址（含 `#debate=`），重新登录后按原地址回到原会话；不静默重试，也不隐藏已提交内容。
- `[设计建议]` 地址无效（会话不存在、已删除或无权限）时进入口页并说明，不自动创建新会话。
- `[设计建议]` 顶栏只在已登录时显示用户名与“退出登录”；退出结果未确认时提供“恢复登录状态”核实，不直接宣称为已退出。

### 2.3 登录失败的文案边界

| 失败类型 | 可显示 | 不可显示 |
| --- | --- | --- |
| 输入不合规（400）`[已确认]` | 哪个字段不合规、如何修改 | 服务端校验细节、内部字段名 |
| 凭据错误（401）`[已确认]` | “用户名或密码错误”，不区分账号是否存在 | 账号是否已注册、密码提示 |
| 用户名冲突（409）`[已确认]` | “用户名已被使用，请更换” | 已存在账号的其它信息 |
| 过频（429）`[已实现]` | “请求过于频繁”＋服务端给出的等待时间 | 限流窗口长度、剩余次数、他人触发情况 |

- `[设计建议]` 登录与注册失败都留在原表单，保留已输入的非敏感字段（用户名），密码框清空；不整页跳转、不清空整页状态。
- `[已确认]` 限流数值与重置口径属服务端与待评估事项，界面不得自行推算或宣称。

## 3. 共通状态与恢复

`[设计建议]` 所有页面共用下表，实现时集中到统一状态组件，禁止各页自行发明文案与行为。

### 3.1 状态总表

| 状态 | 界面表现 | 允许动作 | 禁止 |
| --- | --- | --- | --- |
| 加载中 `[设计建议]` | 骨架或占位＋`aria-busy`，说明正在加载什么 | 等待 | 用空白冒充“没有数据” |
| 空 `[设计建议]` | 明确“暂无 X”，给出下一步 | 去创建、手动刷新 | 用空态暗示失败或已通过 |
| 保存中 `[设计建议]` | 按钮忙碌、相关控件禁用 | 等待结果 | 重复提交、并行保存 |
| 成功 `[设计建议]` | 明确成功反馈，写明已保存的范围 | 继续下一步 | 用成功文案掩盖部分失败 |
| 权限或登录失效 401 `[已实现]` | 就地提示“登录已结束，请重新登录”，保留当前地址 | 重新登录后回原页或原会话 | 静默清空、丢弃已提交内容展示 |
| 不存在或越权 404 `[已实现]` | 统一“不存在或无权访问” | 返回列表或入口 | 泄露资源是否存在，或区分“不是你的” |
| 网络失败 `[已确认]` | 受控提示＋手动重试入口 | 手动重试 | 自动重试、无限轮询 |
| 模型失败 502/503/504 `[已确认]` | 区分超时、不可用、输出无效三类原因 | 手动重试或保存退出 | 把失败当有效结果、自动换模型或换 Key |
| 429·频率限制 `[已实现]` | “请求过于频繁”，可显示服务端给出的等待时间 | 按 `Retry-After` 手动重试 | 编造窗口长度、自动重发 |
| 429·并发占用（本人或全局）`[已实现]` | “当前有生成正在进行”，不透露他人身份 | 按服务端给出的时间等待后手动重试 | 说成“额度已用完”、自动排队 |
| 429·日额度用尽 `[已确认]` | “今日次数已用完”，指向可查看的历史或恢复入口 | 按服务端给出的时间等待、查看历史 | 编造重置时点、说成“模型故障”、承诺立即恢复 |
| 额度限制（非 429）`[已确认]` | 说明是应用侧额度限制并给恢复建议 | 按服务端提示操作 | 说成“模型故障”、承诺立即恢复 |
| 部分分析失败 `[已确认]` | 保留成功部分，逐项标出失败项 | 只补失败部分 | 整场重生成、覆盖成功结果或人工编辑 |
| 定位失败 `[已确认]` | 标为“待核对”，不高亮 | 查看附近原文、手动定位 | 猜一句高亮、静默隐藏 |
| 无模型配置 `[补充草案]` | 说明“需先配置模型服务”，历史与会话详情仍只读可看 | 去设置页配置 | 阻止读历史、反复弹窗、自动弹开设置 |

- `[设计建议]` 上表只定状态与动作；骨架形态、按钮样式与占位文案是实现做法，随统一状态组件演进，不在本文锁定。
- `[已确认]` 表里的“模型失败”只定归类与文案纪律；同一失败在某阶段可做哪些动作（重试、放弃并进入结辩、保存退出）由[辩论工作台 §7](03-workspace.md#7-生成失败与放弃)按阶段规定，本文不重复。

### 3.2 错误码归类（实现现状）

`[已实现]` 前端已有“业务码 → 受控文案”的集中映射（`frontend/src/api/client.ts`），页面只按归类渲染，不直接读 HTTP 状态码拼文案。

| 业务码 | 界面归类 | 实现状态 |
| --- | --- | --- |
| `unauthenticated` | 登录失效 401 | `[已实现]` |
| `not_found` | 不存在或越权 404，不区分是否存在 | `[已实现]` |
| `rate_limited` | 429·频率限制或日额度用尽 | `[已实现]` 文案共用，须拆开（见 §3.3） |
| `generation_busy` | 429·并发占用 | `[已实现]` |
| `model_timeout` | 模型失败·超时 | `[已实现]` |
| `model_unavailable` | 模型失败·不可用 | `[已实现]` |
| `model_error` | 模型失败·输出无效 | `[已实现]` |
| `round_conflict`、`idempotency_conflict`、`attempt_version_conflict` | 会话状态已变化，查询最新状态 | `[已实现]` |
| `dependency_unavailable`、`internal_error` | 服务暂不可用，手动重试 | `[已实现]` |
| `csrf_failed` | 安全校验失败，刷新登录状态后重试 | `[已实现]` |

- `[已实现]` 服务端把模型失败映射为三档，界面按其归类展示而不合并成一句“生成失败”：502 `model_error` 为输出无效（空白、超长、截断、格式不符），503 `model_unavailable` 为上游不可用，504 `model_timeout` 为超时；三者共用“手动重试或保存退出”的恢复路径，但原因文案不互相替代。
- `[设计建议]` 三类失败都不显示上游原始状态码与供应商名称；会话内的失败记录保留可见，供用户判断是否重试。

### 3.3 恢复纪律

- `[已确认]` **429 必须区分三类**：频率限制、并发占用（本人或全局）、日额度用尽。三者恢复方式不同，不得统一提示为“其他生成进行中”，也不得把并发占用说成额度耗尽；[PRD §19.2](../PRD.md#192-与服务额度的边界) 要求应用额度与并发分别说明。
- `[待决]` 服务端目前对“频率限制”与“日额度用尽”返回同一业务码，界面如何在不猜测的前提下区分二者，需接口给出可区分信号；本文不定该接口。
- `[已确认]` **只展示服务端可知的恢复信息**：`Retry-After` 或服务端明确返回的时间口径才可展示；服务端没说时不编造“X 分钟后重试”，也不猜“每日 UTC 0 点重置”这类具体时点。
- `[已确认]` **统一纪律**：不自动重试、不隐式额外调用、不覆盖成功数据与人工编辑（[PRD §10.3](../PRD.md#103-分析失败与重试q33)）。
- `[已确认]` **“停止等待”只停本地等待**：文案须说明不承诺取消上游调用或不计费（[PRD §3.6](../PRD.md#36-生成失败与放弃规则q11q38)）。
- `[已确认]` **错误提示不得包含**：Key 或其任何片段、完整请求头、上游原始响应、堆栈、DSN；正常设置页只允许受控脱敏摘要（[PRD §19.2](../PRD.md#192-与服务额度的边界)）。
- `[设计建议]` 状态组件以“业务码 → 文案＋允许动作”为唯一入口，同一 429 不得被写成同一句提示；文案不出现内部错误码、请求标识以外的实现细节。

## 4. 退出、离开与未提交内容

`[设计建议]` 工作台离开前（切视图、返回入口、结束会话、关闭页签前可拦截的范围）给出一次性说明，不每次切换都弹。

### 4.1 线框

```
┌ 离开本场训练？──────────────────────────────────────┐
│ 已提交并保存：12 条正式发言、批注 5 条、争点卡 4 张    │
│ 未提交：输入框中的草稿不会保存，离开后需重新输入      │
│ 进行中：AI 回复尚未完成，离开不影响服务端状态；       │
│         下次进入可查询结果或手动重试（不自动重新生成） │
│ [继续训练]  [离开]                                   │
└──────────────────────────────────────────────────────┘
```

### 4.2 三类内容必须分开写

| 内容 | 处理方式 | 依据 |
| --- | --- | --- |
| 已提交并保存 `[已确认]` | 发言、当前阶段与回合进度由服务端保存，可继续原场训练 | [PRD §10.1](../PRD.md#101-中途退出与续练q29) |
| 未提交草稿 `[已确认]` | 不保存，也不提供自动保存；离开后需重新输入 | [PRD §10.1](../PRD.md#101-中途退出与续练q29) |
| 在途生成结果 `[设计建议]` | 结果未知，离开不影响服务端状态；下次进入显示恢复或手动重试，不自动重新生成 | [PRD §10.1](../PRD.md#101-中途退出与续练q29) |

### 4.3 规则

- `[已确认]` 不提供草稿自动保存；界面不得暗示“已自动保存草稿”或“已为你保存输入”。
- `[已确认]` 未完成 AI 回应显示恢复或重试入口；刷新不重复生成、不计完整回合。
- `[设计建议]` 说明区分“已提交并保存”“未提交（不会保存）”“在途生成（结果未知，需查询）”，不把在途当已完成。
- `[设计建议]` 关闭页签无法保证拦截，因此不承诺“一定会提示”，文案也不写“已阻止离开”。
- `[设计建议]` 完成或已进入复盘的会话再次进入时按只读处理，离开确认框不再出现。

## 5. 不做什么

- `[已确认]` 不做草稿自动保存，也不以“草稿已恢复”之类的文案暗示已保存。
- `[已确认]` 不做自动重试、自动换模型、自动换 Key 或自动补发以掩盖失败。
- `[已确认]` 不显示 Key 片段、完整请求头、上游原始响应、堆栈或 DSN。
- `[已确认]` 不承诺取消上游调用或不计费，不把“停止等待”写成“已取消生成”。
- `[已确认]` 不虚构额度、余额或重置时点，不承诺立即恢复。
- `[已确认]` 不新增未获确认的入口（草稿自动保存、成长曲线、排行榜等）。
- `[设计建议]` 不在 401/404 时跳转外部页、静默清空页面或自动创建新会话。
