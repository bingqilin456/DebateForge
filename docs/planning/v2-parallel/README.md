# V2 并行设计与交接

基线为 `v2-ui-design-rewrite@0a8c5c4`，含已签收的 V2-03、V2-04 切片。以下四份方案供独立评估、细化和编写 Fake/Mock 验收用例。正式实施须按 [TASKS](../TASKS.md#产品-v2-待分配任务未开始) 分配负责人并取得相应授权。

| 设计 | 负责的功能 | 可独立推进的部分 | 真实链路接入条件 |
| --- | --- | --- | --- |
| [01 训练赛入口与阶段](01-training-flow.md) | V2-01、V2-02 | 正反双方步骤、旧数据兼容、状态机与入口用例 | 先锁定阶段读写契约，并在隔离库验证 |
| [02 争点卡与原文定位](02-issue-cards.md) | V2-06、V2-07 | 用 V2-04 锚点和四轮完赛夹具完成卡片与编辑设计 | 训练赛自动更新等 01 提供已提交的阶段事件 |
| [03 局部重练](03-repractice.md) | V2-08 | 用四轮完赛与本人选段夹具设计主路径 | 批注入口做可选接入，等统一锚点读法 |
| [04 赛后复盘与四维](04-review.md) | V2-10、V2-11、V2-13 | 用完赛会话和已保存分析夹具设计独立复盘 | 雷达等四维结果定型。训练赛读入等 01 提供权威完赛状态 |

- 每份方案由一名负责人端到端维护。并行可写任务各用一个独立 worktree，单独运行单元测试；共享隔离数据库或端口须串行使用。
- 四组先在各自模块和夹具内工作。会话通用 DTO、API/OpenAPI、公共页面、路由、Gate、迁移编号由整合负责人统一落笔与分号段，避免并行争写。持久化方案落定并验证后，再登记接口和迁移。
- 四轮完赛可先用现行会话状态验证，V1 的 `standard_4` 和历史 `quick_3` 继续走原赛制。训练赛接入只消费 01 提供的服务端进度、保存后的发言与完赛信号。
- 先集成 01 的共享契约，再接各消费方。02 的阶段触发和 04 的争点卡跳转可在集成期接入；03 首版主路径可单独验证。PDF、历史三态、训练强度、策略锦囊、异议与模型设置按各自 TASKS 条目排期。
- 回归记录分开写明 Fake/Mock、隔离库、浏览器和真实模型样例。产品规格与 AC 以 [PRD V2](../../product/PRD.md) 为准。
