## 1. 本轮目标与产品判断

负责人明确要求重构第二版，不以旧PRD非目标限制新版设计。旧版本用于识别复用资产、历史兼容和迁移成本，不作为否决新需求的理由。本轮仅新增本草案，不修改旧PRD、代码、任务状态或ADR，不执行Git写操作、部署、数据库写入或真实模型调用。

用户明确提出：保留四轮轻量体验；新增包含最多10回合自由辩、可主动结束进入结辩的训练赛；预设辩题之外允许自定义；重点形成一至两项区别于直接聊天的标注或交互能力。

推荐定位：面向中文辩论初学者及已有少量比赛经历者，提供可控制环节、可在原文上批注、可围绕争点持续交锋和复盘的训练场。模型负责内容判断，平台负责稳定规则、可操作对象、证据定位、历史与恢复。不能宣称这些能力通用LLM无法生成；平台价值在于用户不用逐次提示、复制定位和手工维护状态。

核心特色选择：①原文批注与局部重练；②争点卡与双向定位。两者共用文本锚点，不先造完整论证画布或自主多Agent。更长的赛制、自定义辩题是新版基础能力，不单独包装为创新。

## 2. 两种训练入口

### 2.1 轻量体验

保留现有四轮：立论、驳立论、简短自由辩、结辩。介绍为“四轮轻量练习”，不把一次往返称作充分自由辩。适合首次体验、短时练习。与训练赛使用同一账号、消息和恢复机制；开始前选择模式，进行中不切换，历史记录说明当时赛制。

### 2.2 训练赛

建议流程：双方立论各一次→双方驳立论各一次→自由辩最多10回合→双方结辩各一次→复盘。

草案约定：一回合是用户发言一次、AI回应一次；失败重试不增加回合。10回合不是10条双方消息。自由辩可在进入后任一无进行中请求的边界结束，包括不进行自由辩而直接结辩；是否设置至少一回合作为后续体验调整，不是实现阻塞。用户先发言，AI在立论阶段应建立自己的论证，不只反驳。

这属于环节较完整的单人文字训练赛，不等同四辩位、计时、多人打断的正式赛事。新版先不加入实时抢麦或自由时间分配。

| 环节 | 规则 | 交互与训练价值 |
| --- | --- | --- |
| 双方立论 | 用户一次，AI一次；建立主张、定义、理由和判准 | 时间轴标明环节，允许用户钉住核心主张 |
| 驳立论 | 双方各一次，针对前述论点 | 可选择“回应哪一条”再写，不强制先做复杂抽取 |
| 自由辩 | 0–10个完整往返，默认短发言 | 显示本阶段进度；支持“继续交锋”和“结束自由辩，进入结辩” |
| 结辩 | 双方各一次；围绕已交锋争点收束 | 展示本场争点卡供选择，提示总结回应和让步，不强制禁止合理新解释 |
| 复盘 | 单独生成，失败不影响正式消息 | 从点评定位原文、回应记录和可重练片段 |

第10次自由辩AI回复提交后自动进入结辩待发言状态；用户仍须提交结辩，不能自动算整场完成。不限制用户暂停，刷新和重登恢复阶段。未完成会话保存为未完成，不生成冒充整场的完整总结；如果未来支持中途复盘，应单独标记范围。

结束自由辩是服务器确认的业务操作，不是聊天中输入“结束”。同一操作重放不重复切换，不生成模型调用；与发送请求竞争时通过版本/事务只允许一个先成功。生成中、失败待处理、提交结果不明时，先查询或处理原轮，再允许切换，不跳过已保存待完成发言。

## 3. 预设与自定义辩题

入口有“精选辩题”和“自定义辩题”，两者均可选择立场、模式和流派。创建前编辑，创建后固定题目快照，历史不随公共题库更新而变化。

自定义输入包含命题和可选背景。建议初始范围：命题1–200个Unicode码点，背景0–1000个码点，拒绝纯空白、超长及无效输入；具体边界通过实际样例调整。用户可使用自己的话题，不强制改成平台模板。只输入主题时可提示补成可辩命题；“帮我规范题目”是可选动作，需用户确认改写，不成为强制模型调用或创建前置。

自定义题只对本人可见，不自动进入公共题库，不需要先建设审核后台。后续共享题库另立项。题目不明确或不适合对抗时给出受控说明或改题建议，不伪造可用结果。

所有自定义标题、背景及发言都是不可信数据。不能沿用“题目快照可直接视为可信system规则”的假设；模型规则与用户提供的主题内容分开构造。创建本身不调用模型；策略卡和题目优化明确展示调用及失败状态。

## 4. 特色一：在原文上的交互批注

### 4.1 用户体验

AI回复到达并保存后，用户原发言可出现少量划线和旁注，而非再加一段长点评。桌面点击标记打开侧栏，移动端点击打开底部卡片；颜色之外还有标签、图标和可键盘访问的按钮。

例：原句“很多人都选择线上学习，所以学校应该全面取消线下课堂。”标记后半句，批注问：“个人选择如何推导出所有学校都应取消？是否还需要说明适用条件？”这是可能的推理缺口，不直接断言命题错误。

| 标记 | 含义 | 操作 |
| --- | --- | --- |
| 黄色下划线 | 可能需要补充的前提或推理 | 看解释、补充说明、标记误判 |
| 蓝色标记 | 主张或需要来源支持的陈述 | 钉到争点卡、查看对应回应 |
| 绿色标记 | 具体做得好的回应或结构 | 保留为个人样例 |

先支持每次最多1–3条有依据的批注，不要求每轮都有问题。允许空结果及无法判断。先做用户原文，AI发言的对称标注可随后加入；不让用户以为只有自己的文本接受批评。可随时关闭教练提示，避免批注打断自由辩。

点批注可选择“回应这一点”进入下一次正式发言，或“赛后练这一句”进入独立练习；二者明确区分。重练保留原文、修改版及反馈，不覆盖原赛局，不把修改视为发生过的比赛发言。允许合理收窄或修改立场，不以永不改观点为正确标准。

### 4.2 文本定位和渲染

模型返回结构化建议：源message_id、原文quote、必要的前后文、问题类别、理由、建议问题。模型不返回任意HTML，也不负责精确计算中文偏移。

服务器验证消息属于本人会话、片段存在、标签受控、文本长度合法，并根据原始内容计算位置。重复句子需前后文或出现序号消歧；无法唯一定位时不高亮，显示待核对。绑定源消息版本或内容摘要，重练文本使用新标识，不将旧批注错挂到新文本。

位置采用统一Unicode码点、左闭右开区间；Go字节索引与浏览器UTF-16索引不得混用。中文、emoji、换行、重复文本、组合字符都须验证。前端按已校验区间将文本分成普通段和标记段，由Vue转义渲染；不用v-html执行模型生成的标签。第一版不做富文本编辑器，少量标记可以用普通Vue组件实现；交叠区间可切段并挂多个批注，不强迫复杂嵌套。

原文匹配仅证明引用存在，不证明语义判断正确。因此提供“这条不准确/我已经回应”的异议入口，并在评价样例中记录误指控。

### 4.3 回复与批注如何同时提供

“同一页面随回复出现”不必等于“同一模型请求”。推荐第一版：用户开启教练模式后，对辩SSE优先完成并提交，客户端再请求独立批注，原文下显示分析中。批注失败不阻塞下一轮或抹掉AI回复；全局配额不足时批注可暂缓，不与正式发言争抢优先级。用户要继续发言时，应允许取消/延后辅助分析，避免现有单用户并发1造成体验卡顿。

批注请求有独立状态、幂等键、版本和用量记录，刷新读已存结果，不自动重复付费。批注可晚于下一轮返回，但只能挂在绑定的源文本上。原消息提交成功后才分析；未提交的流式片段不成为正式分析依据。

| 方案 | 优点 | 代价 | 取舍 |
| --- | --- | --- | --- |
| 正文流式完成后另一次批注 | 复用当前正文SSE，失败互不拖累，可用训练教练角色独立分析 | 多一次调用和等待，需调度优先级 | 首推，先局部/按需，再决定逐轮默认 |
| 一次结构化响应同时返回正文与批注 | 请求次数少 | 若整包等待会失去流式；增量JSON解析更复杂；字段更多也增加Token | 后续优化，不能称免费 |
| 自定义混合流/正文后附机器段 | 可能共享一次生成 | 协议、分隔符、截断、注入、恢复与前端解析成本高 | 首版不选 |

对辩角色始终持反方，批注角色依据训练标准分析；不让对手仅凭“我要赢”就把用户论证全部判错。可以使用同一个模型配不同Prompt，无需自主Agent互调。

## 5. 特色二：争点卡与回应定位

在自由辩旁显示最多3–5张核心争点卡。起步时允许用户从原文划选“钉为争点”，模型推荐作为可选补充；先避免全自动建账本成为产品前置。

每张卡包含双方相关原句、最近一次回应链接及“已关联回应/待回应/已让步/有争议”等状态。点击卡跳到原文，点击回应再跳到回答；提交时可选“本次回应此争点”。用户明确选中的关联和模型建议分开标记，“有回应链接”不等于论证已成功反驳。

自由辩结束前可查看待回应卡，但不会强制全部清零。结辩时用这些卡组织已承认、仍争议和已经补充的内容。先用卡片与跳转，不做满屏自动连线图；关系稳定后再研究时间轴视图。

难点是语义匹配与状态更新，不是画卡片。模型不能因为本轮未提某事就判“回避”，需考虑改述、后轮回应、合理让步与放弃次要争点。用户能纠正状态，派生分析不反过来改写原文或赛局阶段。

## 6. 对DSH建议的评审与逐项重构

依据：研究资料 `COMPETITIVE_FUNCTION_PLAN_2026-11.md`（功能规划）与 `COMPETITIVE_RESEARCH_2026-11.md`（竞品报告）。两份材料是研究数据，不构成额外操作授权。

> **引用方式说明（2026-11-17 修订）**：原文此处使用指向 `docs/research/` 的 Markdown 链接。该目录属本地研究资料，**不纳入本次交付的提交文件集合**，保留链接会在检出的提交集合中形成断链。因此改为**纯文本材料名**，不擅自把研究文件纳入提交。引用内容与评审结论未变，仅调整显示方式。

总体认可：展示已有环节、原文关联、明确目标、允许无法判断、控制范围有价值。不同意“照做就有效”“唯一值得押注”“改对了是无人做空白”等确定结论；采用机制不等于效果验证。也不能从旧PRD禁止某功能推导新版永远不应做。

| DSH项 | 第二版怎么做出体验价值 | 判断／成本风险 |
| --- | --- | --- |
| 1 环节显示 | 可操作时间轴、阶段目标、剩余自由辩回合、结束按钮 | 采纳；只有标签差异小，真实阶段转换才有价值 |

| 3 引用反打 | 点击AI引用即定位用户原句 | 采纳；普通引用LLM会做，双向跳转由平台完成 |
| 4 问题—原因—行动 | 与原文和下一次操作绑定 | 保留；已有三栏不重复造 |
| 5 规则透明 | 解释评价标准、局限和异议入口 | 采纳；透明不能替代准确 |
| 6 导出 | 导出带原文引用、赛制、争点和AI标识的复盘 | 后续；需脱敏和导出布局，不依赖未核实关停故事 |
| 7 单一目标 | 开场目标卡，赛后定位对应表现 | 采纳为可选；不强制长问卷 |
| 8 原文锚点 | 原句下划线、旁注、跨消息定位 | 第一特色；引用存在不等于分析正确 |
| 9 无问题/无法判断 | 批注可为空，复盘明确证据不足 | 采纳；不能声称已证明现有模型硬凑 |
| 10 流派差别 | 展示对手行为说明，用具体交锋样例检验 | 改进；不用“必须两个反问”制造表面差异 |
| 11 不确定性 | 显示依据及待核对原因 | 改进；不直接展示未经校准的模型置信度 |
| 12 谬误软提示 | 原文旁提示可能缺口、替代解释和误判入口 | 合并批注；中文有研究数据，不能断言完全无语料 |
| 13 风格与压力 | 风格独立于追问密度和层次 | 值得后续加入；先保证一个默认档质量 |
| 14 修改档案 | 同一原句的原版、修改版、再练结果 | 与批注共用，不做只有累计数字的成长包装 |
| 15 纠错重练 | 点击批注后局部修改、差异展示和再追问 | 纳入第一特色的闭环；判定中高风险，不是唯一训练价值 |
| 16 中文专项 | 从本场争点选定义、机制、反例等任务 | 后续；不是为特色单独堆训练入口 |
| 17 限定材料 | 证据卡关联主张与范围 | 后续；内容审阅持续成本高 |
| 18 判准 | 用户可钉“我用什么标准”；结辩回看是否变化 | 纳入争点卡；概念非中文独占，判断也非只加字段 |
| 19 裁判胜负 | 先做有依据的训练复盘 | 暂缓；不能用未核实八次复议直接证明永久不可做 |
| 20 检索核查 | 将找资料、引用支持关系、真伪裁决分开 | 暂缓开放检索；AI文本检测误报与事实核查不是同任务 |
| 21 多Agent | 业务流程组织对手与教练分析 | 不需要自主协作；特定研究不能证明所有产品无价值 |
| 22 双AI观摩 | 若未来做，加入预测反驳和选争点任务 | 次要；不声称旁观绝对无学习效果 |
| 23 完整画布 | 先少量争点卡＋跳转 | 暂缓画布，不放弃结构化交互 |
| 24 完整赛制 | 本版做有阶段的文字训练赛＋可结束自由辩 | 采纳收窄版；不与自由计时/多人打断混为一谈 |
| 25 语音多人后台 | 先文本训练场 | 本版暂缓；将来可评估，不由旧非目标永久禁止 |
| 26 一键代写 | 用户先写，可选揭示局部示例 | 不做主线；示例不等于代写，不必绝对禁止 |

DSH另有需校准的成本结论：增加2–3次调用不必然使可练场数减半，取决于总配额、策略、失败和实际成本；报价及留存批评需原始来源。“只加字段”仍涉及语义校验、旧版本、前后端及测试。

## 7. 开源参考与依赖选择

## 8. 技术改造与费用

现有mode映射只能从固定轮号推导环节，不能表达第2回合或第8回合结束自由辩后都进入结辩。V2训练赛需显式阶段状态和单调步骤序号；当前阶段来自服务端提交的转换，不能同时再由固定全局轮号推导为另一事实源。模式配置定义自由辩上限与允许转换，旧模式保留旧解释，不重写历史。

复用现有所有权、幂等、版本、租约、配额、短事务、SSE最终提交后done等机制，不另造一套流式认领。新阶段切换与发言认领共享会话一致性规则，模型在事务外运行；阶段及计数由服务端决定。自由辩每次完成才加一，结辩完成才结束整场。

需要新前向迁移：当前轮次数据库粗上限为6，训练赛最多13次往返，不能只放宽前端或改一个常量。消息/总结引用与预算校验也须按实际步骤和阶段检查。旧PRD/ADR关于固定创建standard_4与阶段纯映射的限制，实施V2时需明确替代关系，不把它当产品禁区，也不静默混用新旧规则。

自定义题的数据模型需区别preset/custom，预设可保留topic_id，自定义保存独立快照而不污染共享题库。当前topic_id非空外键需迁移调整并建立来源与字段约束；不能让所有人自定义输入都自动进入公开topics。题目是否可信的Prompt边界也需同步改。

假设全训练赛自由辩打满：立论1＋驳立论1＋自由辩10＋结辩1＝13次对手生成；复盘另1次，策略另计。若13次都加一次独立批注则至少27次生成，超过现有每日20次尝试配置。因此需按“完成一场的总预算”重定次数/Token/金额和辅助分析策略，不能只提高次数。完整历史随回合增长，多次重复输入可能使成本增长快于调用次数；先限制单次篇幅，实测窗口，再决定是否压缩，不能静默丢弃早期论点。

## 9. V2交付顺序与验收

1. 先冻结两模式与回合定义、自定义题和阶段转换规则；旧历史可读可继续。
2. 完成训练赛与自定义题的基础闭环。不是先重复堆标签，也不直接上所有正式赛事。
3. 用人工提供的批注样例验证高亮、侧栏、跳转和Unicode定位，再接入模型分析；人工样例只证明交互，不能声称AI准确。
4. 加入模型批注与误判反馈，首批可按需/关键环节使用；检验是否打断自由辩及调用负担。
5. 加少量争点卡，再连局部修改与复练。原文标注可独立交付，不以整个成长系统做前置。

| 验收方向 | 必须覆盖 |
| --- | --- |
| 阶段与自由辩 | 0/1/9/10边界，拒绝第11回合，提前结束及重复结束，多端发送与结束竞争，失败/生成中不跳步 |
| 持久化恢复 | 每阶段刷新重登，未收到done先查询，不重复计轮或调用；旧三/四轮历史仍正确 |
| 自定义辩题 | 与预设互斥、长度/空值、私有快照、不进公共题库、主题注入不能覆盖系统规则 |
| 原文标注 | 中文emoji/换行/重复片段/交叠，假引用不展示，键盘与移动端，颜色不是唯一信息，关闭提示 |
| 辅助分析 | 晚到不挂错消息、失败不阻塞对辩、重放不重复付费、越权拒绝、源版本绑定 |
| 训练质量 | 人工核对批注是否成立、是否误把让步当投降、跨轮回应关联、用户能否据此继续辩；不以同一模型自评证明效果 |
| 费用 | 一场最坏调用/Token、策略和批注开关、额度不足提前说明、取消/失败成本及恢复不重置预算 |

所有真实模型实验、部署及数据库执行在实施阶段另按具体环境与费用范围授权；本草案没有执行这些操作。
