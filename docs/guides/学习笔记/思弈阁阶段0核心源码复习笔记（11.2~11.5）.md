# 思弈阁（DebateForge）· Bootstrap 核心源码复习

> [!info] 范围
> 汇总用户在本项目三段学习对话：**代码准确性审查、解释路由分发、Bootstrap 导师式问答**。以实际健康检查链路为主，保留代表性的「我的回答 → 纠正」。问答有少量压缩、归纳，非逐字聊天记录；依据当时的代码说明，不代表重新拉取源码或运行验证。

## 0. 一张图记住全链路

```text
后端启动：main → LoadConfig → net.Listen(:8080) → NewRouter
         → http.Server{Handler: Gin} → server.Serve(listener)

前端启动：main.ts → App.vue / onMounted(checkHealth)
         → health.ts / getLiveHealth()
         → client.ts / requestJson() → fetch('/health/live')

请求：浏览器 :5173 → Vite 代理 → Go :8080
      → Gin 中间件 → GET /health/live → live(c)
响应：HTTP 200 + {"status":"alive"} → Vite → client.ts
      → health.ts 校验业务字段 → App.vue 更新 ref → 页面显示成功
```

**一句话：** `App.vue` 管页面，`health.ts` 管接口契约，`client.ts` 管 HTTP，Vite 管开发代理，Gin 管路由和处理。

## 1. Go 服务启动与配置

| 组件 | 作用 | 易混点 |
|---|---|---|
| `main()` / `run()` | 日志、退出信号、服务组装 | 启动入口与业务路由分开 |
| `LoadConfig()` | 读取并校验 `HTTP_ADDR` | 没设置 ≠ 设置为空 |
| `net.Listen("tcp", addr)` | 绑定 TCP IP/端口、创建监听器 | **不是**注册 HTTP API |
| `NewRouter(logger)` | 创建 Gin Engine、注册路由和中间件 | 注册 ≠ 执行 Handler |
| `http.Server{Handler: router}` | HTTP 服务使用 Gin 处理请求 | Gin 实现了 `http.Handler` |
| `server.Serve(listener)` | 接受连接、处理并分发 HTTP 请求 | 没调用它，不能正常提供 HTTP 服务 |
| `Shutdown(ctx)` | 优雅停止接收新请求并等待已有请求 | 本项目超时后会 `Close()` |

**配置速记**

```go
addr, present := os.LookupEnv("HTTP_ADDR")
if !present { addr = "127.0.0.1:8080" }
host, portText, err := net.SplitHostPort(addr)
ip, err := netip.ParseAddr(host)
port, err := strconv.Atoi(portText)
// 要求：ip.IsLoopback() && 1 <= port && port <= 65535
```

- 默认：`127.0.0.1:8080`；允许 `127.0.0.1:8081`、`[::1]:8080`。
- 拒绝：空字符串、`0.0.0.0:8080`、`localhost:8080`、端口 `0`。
- `127.0.0.1`：回环地址，仅本机访问；`0.0.0.0`：监听所有 IPv4 接口，不是供其他电脑直接填写的目标 IP。能否远程访问还受防火墙影响。
- `os.LookupEnv()` 不会主动读取 `.env`；需把变量注入进程环境（可借助 dotenv，但非唯一方式）。

> [!question] 典型问答：启动顺序
> **问：** 8080 已占用，`NewRouter()` 还会执行吗？
> 
> **我的回答：** “不会，因为在 `net.Listen` 就因为端口被占用而停止。”
> 
> **导师纠正：** 结论对；准确地说 `net.Listen` **返回 error**，`run()` 检查错误后提前 `return`，所以 `NewRouter()` 不执行。并非 `net.Listen` 主动杀死进程。

> [!question] 典型问答：自己实现 Handler
> **问：** 不用 Gin，能否自己提供 `http.Server.Handler`？
> 
> **我的回答：** “可以，实现了同一个接口，就可以使用同一个方法。”
> 
> **导师纠正：** 需要准确说出：实现 `ServeHTTP(http.ResponseWriter, *http.Request)` 即满足 `http.Handler`；Go 接口是**隐式实现**，Gin Engine 也如此。

## 2. Gin Router、Handler 和 Middleware

```go
router := gin.New()
router.GET("/health/live", live) // 注册 GET + 路径，非立即调用

func live(c *gin.Context) {
    c.Header("Cache-Control", "no-store")
    c.JSON(http.StatusOK, gin.H{"status": "alive"})
}
```

- **Router**：依据 HTTP 方法和 URL 路径，查找对应的 Handler。
- **Handler**：真正处理请求、返回响应。
- **`gin.Context`**：当前请求的上下文，可读取请求、设置响应头和写 JSON；即使无需读取参数，`live` 也用它写响应。
- **Middleware**：请求 ID、日志、统一异常等公共逻辑。`c.Next()` 进入后续处理链并在结束后返回；`c.Abort()` 阻止后续**尚未执行**的 Handler。
- **`return` 只退出当前 Go 函数**，不等于 `c.Abort()`；鉴权失败通常用 `c.AbortWithStatusJSON(401, ...)` **再 `return`**。

**顺序例子：**

```go
func MW(c *gin.Context) {
    fmt.Println("A")
    c.Next()
    fmt.Println("B")
}
func H(c *gin.Context) { fmt.Println("C") }
// 输出 A C B
```

> [!warning] 我踩过的坑：不写 c.Next() 就一定不执行 Handler？
> **我的回答：** “不会，因为 Handler 在 `c.Next()` 中，必须执行 `c.Next()`。”
> 
> **导师纠正：** **错误。** Gin 外层已经启动处理链；若中间件没有 `Next`、也没有 `Abort`，正常返回之后外层循环仍会继续执行后续 Handler。比如中间件 `print("A"); return`，Handler `print("B")`，结果通常是 `A B`。
>
> **关键区别：** `Next()` 控制**何时继续**，`Abort()` 控制**是否继续**，`return` 控制**当前函数是否结束**。

> [!question] 典型问答：Abort 与 return
> **问：** `AbortWithStatusJSON(401, ...)` 后不写 `return`，下面的 `fmt.Println("结束")` 会执行吗？
> 
> **我的回答：** “会执行，Abort 不会自动 return；业务 Handler 不会执行。”
> 
> **导师评价：** 正确；这正是 Gin 处理链和 Go 函数控制流的区别。

## 3. Vue、Vite、fetch 与 JSON

| 文件 | 职责 | 关键行为 |
|---|---|---|
| `main.ts` | 挂载 Vue | `createApp(App).mount('#app')` |
| `App.vue` | 页面交互与响应式状态 | `onMounted(checkHealth)`；成功设 `success`，失败设 `failure` |
| `health.ts` | 健康接口数据契约 | `getLiveHealth()` 校验对象及 `status === 'alive'` |
| `client.ts` | 通用 HTTP 请求 | `fetch`、HTTP 状态、`Content-Type`、JSON、超时、错误归类 |
| `vite.config.ts` | 开发服务器与反向代理 | 浏览器访问 `5173`；`/health/` 转发至 `8080` |

**注意：** `fetch('/health/live')` 是相对路径；页面在 `127.0.0.1:5173`，**浏览器请求的是 5173**，Vite 才去连接 8080。开发代理统一 Origin、简化跨域处理，**不等于把后端变成安全不可访问的服务**。

```text
HTTP 状态码：200           → client.ts 看 response.ok
JSON 响应体：{"status":"alive"} → health.ts 校验 status
Vue 页面状态："success"   → App.vue 控制显示
```

**JSON 的方向别弄反：**

```text
前端发 POST：JS 对象 → JSON.stringify() → JSON 字符串请求体
              Content-Type: application/json（声明请求体类型）
后端收 POST：Gin c.ShouldBindJSON(&dst) → 解析 JSON / 绑定 Go 结构体
后端发响应：c.JSON(...) → JSON 响应
前端收响应：await response.json() → 解析为 JS 数据
```

`Content-Type` 是媒体类型声明：在**请求**中描述请求体，在**响应**中描述响应体。`health.ts` 不是 Vue 的内置特殊文件名，而是本项目封装健康 API 的模块。`ShouldBindJSON` 用于有 JSON 请求体的接口，当前 **GET /health/live 不需要它**。

> [!warning] 我踩过的坑：5173 还是 8080？
> **我的回答：** “实际请求的是 8080，通过 5173 的 Vue 代理转发。”
> 
> **导师纠正：** 浏览器直接请求 **5173**；执行代理的是 **Vite 开发服务器**，而不是 Vue；Vite 再转发到 **8080**。

> [!warning] 我踩过的坑：HTTP 200 + `{"status":"ready"}`
> **我的回答：** “因为状态码没有改成 success，health.ts 根据状态码判定失败。”
> 
> **导师纠正：** 混淆了三层状态。HTTP `200` **已成功**；`"ready"` 是 JSON **业务字段**，不等于约定的 `"alive"`；`App.vue` 最终设置页面状态 **`failure`**（不是 `fail`）。

> [!question] 典型问答：修改 Go 端口
> **问：** Go 改成 `8081`，Vite 仍代理 `8080`，会怎样？
> 
> **我的回答：** “浏览器请求 5173，Vite 转发 8080；Go 在 8081，转发失败。”
> 
> **导师补充：** 正确。修改 `frontend/vite.config.ts` 的 `target`；Vite 通常会自动检测配置变更并**重启开发服务器**，不必一概手动重启；未生效再人工重启。

## 4. 异步、错误处理与安全

- `async` 函数返回 `Promise`；`await` 等待结果，**不阻塞浏览器主线程**。
- `fetch` 遇到 HTTP 404/500 **通常不自行抛异常**：要检查 `response.ok`；网络失败/取消等才会使 Promise 拒绝。
- `AbortController` + 3 秒定时器：取消 fetch，也可能取消**尚在读取的响应体**；不保证 Go 后端计算立刻停止。
- `finally` 重置 `inFlight = false`：成功或失败后都允许重新点击；当前健康检查没有自动重试循环。

| 现象 | 当前归类 | 关键依据 |
|---|---|---|
| 收到 HTTP 500、Vite 返回 502 | `http` | **收到了**非 2xx HTTP 响应 |
| fetch 无法拿到 HTTP 响应 | `network` | 网络通信失败 |
| 超过 3 秒触发 `abort()` | `timeout` | 超时取消（含响应体读取） |
| HTTP 200 + `text/html` | `format` | 内容类型不符合 JSON 契约 |
| HTTP 200 + JSON 声明，正文完整但 `{broken` | `format` | JSON 语法非法 |
| HTTP 200 + `{"status":"ready"}` | `format` | JSON 合法，但业务契约不符 |

> [!warning] 我踩过的坑：`{broken` 还是 timeout？
> **我的回答：** “响应体缺失、无法解析，所以超时。”
> 
> **导师纠正：** 若服务器**已经完整发送** `{broken`，就是**非法 JSON → `format`**。只有等待响应体时**超时触发 `controller.abort()`**，才归类为 `timeout`。响应体中途断开，也不必然叫超时。

> [!question] 典型问答：AI Agent 错误处理
> **我的回答：** “后端记录错误日志；前端返回 code 和错误 ID；client 匹配错误；App.vue 展示简短提示、请求 ID 和重试按钮。”
> 
> **导师补充：** `error_code` 说明**哪类问题**，`request_id` 定位**哪一次请求**；后端日志也必须**脱敏**，绝不记录明文 API Key/Token。当前 `client.ts` 只有基础错误分类，未来业务码映射需要另行实现；AI 生成重试还应考虑幂等性。
