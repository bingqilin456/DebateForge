### 环境负责人启动（PowerShell 7.2+）

先核对 Git HEAD、原仓库、端口/PID 归属及固定测试容器，沿用 [MySQL 说明](../../infra/mysql/README.md) 和 [SSE 启动说明](../../infra/sse/README.md)。已到 00013 的库不再迁移。已有他人服务或生成进行中就停止协调；不能为恢复额度而重启、换账号或删除数据。

1. 核实 `APP_ENV=test`、`AI_MODE=fake`、`T15_FAKE_SCENARIO=slow`。正常使用已有密码文件启动 `infra/sse/start-local.ps1`；它固定 test 目标、先构建当前源码，不自动迁移或播种。生产源码变化时先确认本轮自己的旧服务已正常停止，不能覆盖运行中的二进制。若已有 B2 Fake 正在运行，必须同时核实其 PID/启动来源、真实构建版本和 backend/启动脚本与固定 SHA 无差异，才可复用；显式登记 `source_equivalent_to`，不得把旧版本改写成新构建。
2. Nginx 未被占用时，正常运行 `infra/sse/start-nginx.ps1`，使用仓库已有锁定镜像与实际代理模板。该脚本会核查既有同名容器的标签及挂载；不要用它接管别人正在使用的代理。
3. 前端依赖已安装则不重装。只打开页面可在 `frontend` 执行 `npm run dev -- --config e2e/b3.vite.config.ts`，访问 `http://127.0.0.1:5173/`。普通开发继续使用原 `npm run dev`；两种方式不能同时占用 5173。
4. 自动补验会自己启动/停止专用 Vite，先结束自己的手动 Vite。复用已有浏览器，不要求下载新依赖。明确核实模式、进程和固定 SHA 后，才准备本机忽略目录 `.cache/b3-live-env.json`：

  "source_equivalent_to": "仅复用已核实同源码 B2 时填固定 SHA，否则不填",

这只是结构样例，不能直接当作 ready 记录。核实后才填真实版本、`status=ready` 和本机 PID 等非秘密来源信息；不保存密码、Cookie、CSRF、密钥或 DSN。受限会话无法启动 Docker/读取密码文件时由环境负责人在正常用户会话完成，不尝试绕过限制，也不把旧二进制冒充固定 SHA 新构建。用例只接受实际固定 SHA 构建，或已登记的 B2 构建 `270eed81ee9a29f53bc25c25cb9a9992e8b50252` 且现场 Git 差异核实后端源码一致，不接受任意旧版本。

## 2. 一次完整练习怎么操作

1. **注册后再登录**：用户名 3–32 位 ASCII 字母、数字或下划线；密码 12–128 个 Unicode 字符、最多 512 字节。注册成功不自动登录，请切回登录。请求结束表单密码清空不是账号丢失。
2. **选题、立场和流派**：打开“辩题列表”，选题并选自己的正/反方，AI 持相反立场。四种流派为逻辑型 `logical`、进攻型 `aggressive`、共情型 `empathic`、数据型 `data`；默认 logical。“辩论主视图”也能创建。创建只保存会话，不调用模型；不提供赛制选择。
3. **创建后核对**：页面显示后端保存的题目、立场与流派。创建成功前按钮等待；成功后进入同一个会话。结果未知时先查历史，不再点创建，以免产生新会话。创建后不能修改流派，新会话为 standard_4。
4. **策略可跳过**：“查询策略状态”只读取已有状态，不消耗模型生成；“生成赛前策略”才请求新生成。没有任何 turn 时才能首次生成或失败重试。已有任何发言（包括 failed/generating）后，不再提供首次生成/重试，但可读已有策略。不要强迫自己先生成才能发言。
5. **逐轮发言**：按“立论 → 驳立论 → 自由辩 → 结辩”四轮提交。临时流式片段不等于正式保存；确认完成后才增加轮数并进入下一轮。请只点一次，等待中输入/发送锁定。
6. **复盘总结**：第四轮正式完成后自动请求总结；成功显示具体轮次的优点、问题和建议。失败时先查询，再由用户显式重试，不刷新碰运气自动补调。这里没有比赛总分、排名或胜负判定。
7. **刷新与重登**：刷新可按地址中的会话 ID 重读；退出再登录后打开“本人历史会话”，查看题目、立场、流派、状态、完成轮数及本地时间，选中记录继续由主视图读详情。历史的分页和刷新不会创建新会话或生成回复。

旧 quick_3 历史仍按三轮完成，不能根据本指南的四轮流程改写其上限；界面上限以服务端会话为准。

## 3. 出错时怎么做

| 看到的情况 | 正确操作 | 不能做什么 |
| --- | --- | --- |
| 策略 `generating` / HTTP 202 | 等待有限查询或点“查询策略状态” | 刷新、重复点击不能变成新的生成 |
| 策略 `failed` | 点“查询最新重试版本”，再显式确认重试；版本来自这次 GET | 不把旧版本递增猜测后重发，不绕过已有 turn 限制 |
| 连接断开、未收到 start 或 done、刷新时流中断 | 用原 client_request_id 从本人详情定位；completed 读结果，generating 有限查询，failed 才按查询版本显式重试 | 不换新键重发，不把临时文字当作保存成功 |
| 点“停止等待并查询” | 结束当前等待并查询服务器最终状态，原文保留 | 不是删除发言、取消计费或保证服务端回滚；真实模式中途停止仍可能计费 |
| HTTP 409 | 只重新查询；用户核对最新状态后再决定 | 不自动换键/版本重发，不盲目新建会话 |
| HTTP 429 / 额度或窗口停止 | 等待分钟限流或结束体验，由 A 核实批准窗口和额度 | 不靠重启、删账本、换账号或重新建环境补额度 |
| 认证失效 / 非本人记录 | 重新登录、从本人历史选择；检查是否拿错 ID | 不借他人的会话或 Cookie 继续 |
| 创建响应丢失 | 先到本人历史核实是否已经创建 | 创建非幂等，不能自动再建 |

关闭网页不会删除 MySQL 数据。测试结束仅停止本次自己启动的 Vite、已核对路径的 Go PID 和本地 Nginx；继承的测试库保持原状态，不停整个 Docker、不删除卷或合成历史。独立 Demo 的持久 stop/账本操作只按 A 的运行说明和对应新授权执行。
