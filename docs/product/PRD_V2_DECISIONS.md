## 重要：版本命名边界（2026-11-17 追加核实）

本轮重构核实到一处真实存在的命名风险，已单独处理，避免文档间混称：

- 既有 [ARCHITECTURE 的「总结 Schema 升级（V2）」](../architecture/ARCHITECTURE.md#总结-schema-升级phase3-summary-v2历史当前-phase-3-语境) 与 [TASKS 的 T14-REPORT](../planning/TASKS.md#phase-3赛制流式破局亮点与质量攻坚) 所指的「V2」，是 **`schema_version = 2`** 的总结增强格式：四维 `argumentation` / `rebuttal` / `logic` / `presentation` 各 **0–100 整数**，属 V1 产品基线下 Phase 3 的 P1 目标（T14-REPORT，状态仍为「未开始」）。
- 本轮确认的**产品 PRD V2** 使用另一套四维：论证结构 / 回应针对性 / 证据使用 / 概念与范围，档级 **1–4 + 观察不足**（`v2-training-reference`），且**尚未实施**。
- 两者**不是同一件事**，不得互相引用字段名、取值或实现状态；0–100 与 1–4 不得互换。
- 产品 V2 的四维形态**已由 Q46、Q49 确定为 1–4 档 + 观察不足**，不属于未决项，不得表述为「是否改用 0–100 待决定」。仍未决的仅是**技术兼容范围**：旧的 `schema_version=1/2` 历史数据如何继续读取与展示，以及产品 V2 新结果采用哪个 schema 版本与迁移方式（[TE-08](../planning/PRD_V2_TECHNICAL_ASSESSMENT.md#5-集中登记的技术待评估项)）。
- `phase3-summary-v2` 作为 V1 基线下 Phase 3 的 P1 目标（T14-REPORT，状态「未开始」）继续有效，其任务状态、负责人、估算与 AC14 均不因本轮改写。
- 处置：三类命名（产品 V2、`phase3-summary-v2`、`v2-training-reference`）已在 [ADR-027](../decisions/DECISIONS.md#adr-027-v2-需求基线与版本边界)、[ARCHITECTURE](../architecture/ARCHITECTURE.md#总结-schema-升级phase3-summary-v2历史当前-phase-3-语境)、[TASKS](../planning/TASKS.md#产品-v2-待分配任务未开始)、[GLOSSARY](../../GLOSSARY.md#版本命名防止混称) 与 [API](../api/API.md#当前-v1-契约与-v2-待设计的边界) 统一显式分名。旧格式保留历史/当前 Phase 3 语境，新产品目标独立标注未实施。
