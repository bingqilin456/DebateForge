## 7. 本轮代码改动（同一轮内完成）

1. **账本停用语义**（`backend/internal/ai/demo_ledger.go`）：结果由单一 `halted` 细分为三种 `outcome`——
   - `success`：正常完成；
   - `failed`：单次业务失败但**用量已知且不超预留**，费用已被预留覆盖，只标记该次、账本继续放行；
   - `halted`：用量或控制面无法确认（usage 未知/超界、`stop`、批准或 manifest 变化、窗口失效、记录损坏），整个窗口停用。

   重开账本的扫描路径同样按此区分（`demoOutcomeResumable`）。`failed` 与 `success` 一样占用 `max_calls`、每日额度与费用上限，不退回预留。`internal/ai/demo_test.go` 增补了对应断言，明确 `failure`/`timeout`/`cancel` 三类「费用可覆盖」的失败不得停用窗口、重启后仍可接受新调用。

2. **策略 Prompt 升版**（`backend/internal/ai/strategy.go`）：`strategy-v1` → **`strategy-v2`**，增加显式 JSON 骨架与「禁止代码块标记、解释段落、前后缀寒暄」约束，字段与 schema 未变。依据仓库约定「修改措辞时升级对应版本」。历史策略继续返回保存版本，不因升版重生成。

3. **删除 `backend/cmd/t04-smoke/`**（3 个文件）：其 `main()` 早已固定返回 `BLOCKED`，428 行实现与 12 个测试不再承载任何可契约或可执行路径。同步修正 [文档导航](../README.md) 与 [T04 验收记录](T04_AI_ACCEPTANCE.md) 中会失效的链接。

## 8. 本轮操作失误（如实登记）

**补充授权启动时使用了未重建的旧镜像，导致第 1 项的账本修复未生效。**

- 改动 `demo_ledger.go` 的时间为 2026-11-17 16:25（Asia/Shanghai）；`siyige-p3-demo-app:local` 的构建时间仍为 2026-11-16 07:04，容器内 `/usr/local/bin/server` 时间戳同为 11-16 07:04。
- 因此补充授权期间运行的仍是「单次失败即全停」的旧二进制。会话 25 的总结失败后，账本按旧语义写入 `stop` 并停用，随后两次重试被 503 拒绝。
- 若镜像已含修复，该次失败应记为 `failed` 并允许继续调用，会话 25 的总结与第 5 场都有机会完成。
- 这是执行流程缺陷（未在切换账本卷并启动前重建镜像、未在启动后核对镜像时间戳），**不是代码缺陷**。代码修复本身已通过 build/vet/test/race 验证，但**其运行时效果尚未在真实调用中验证**。
