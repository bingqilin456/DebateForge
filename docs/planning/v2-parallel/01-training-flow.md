# 01 训练赛入口与阶段推进

范围为 V2-01、V2-02。对应 [PRD §2–3](../../product/PRD.md#2-训练模式与入口)、[开始练习](../../product/ui/02-entry.md)与[工作台](../../product/ui/03-workspace.md)。验收重点为 AC-V2-02～09、23、31 中与赛制、步骤和恢复有关的部分。

## 设计与边界

- 入口并列展示四轮轻量和完整训练赛。首次默认轻量，训练赛直接可选。复用 V2-03 辩题快照并在创建前确认立场和模式，创建动作零模型调用。会话创建后固定模式；四轮仍使用现行轮次规则。
- 训练赛由服务端记录权威的阶段、已完成自由辩回合、下一步骤和发言方。正式发言记录有稳定 ID、全局步骤序号、阶段与阶段内序号。前端从服务端读取进度，SSE 只承载增量展示，刷新和断线后重新查已保存状态。
- 顺序按 PRD 执行。立论和驳立论由正方先，结辩由反方先，自由辩每回合由用户先。覆盖 AI 开场、AI 连说两步和用户连说两步。1 回合时共 8 条正式发言，10 回合时共 26 条。
- 进入结辩需要至少一个完整回合。第 10 回合后只提供显式推进。推进和提交发言按版本竞争，只有一个成功；推进可幂等重放、零模型调用。失败放弃严格按 PRD §3.6，仅用于其明确允许的自由辩情形。失败或临时流片段不计正式发言。
- 普通与 SSE 复用同一认领、版本、租约与配额内核。提交成功后才发布正式保存和 `done`。旧会话按原模式读写，分支选择来自服务端会话记录。

## 给并行模块的输入

只读提供会话 ID、模式、权威完赛状态与已提交发言快照。供争点更新消费的事件语义为双方驳立论完成、完整自由辩回合完成、结辩完成；可用会话及完成位置去重。具体 DTO、存储和事件分发方式由本组设计评估，与整合负责人统一进 API 和架构文档。

## 执行与验收

1. 先做双方立场的状态转换表，再用表驱动测试覆盖 0、1、10、越界、失败放弃、AI 开场与跨阶段连续同方。
2. 在 Go service/repository 内复用认领路径。验证同幂等键重放、发言与结束并发、租约恢复和最终写失败，跑 `go test -race ./...`。
3. 入口与工作台用 Mock 验证首次默认、两模式标识、断线重查和按钮禁用。检查旧四轮与历史三轮仍能继续、旧记录不重写。浏览器用例需覆盖两种用户立场。
