# V2-03 私有自定义辩题设计

依据 [PRD §4](../product/PRD.md#4-辩题预设与自定义)、[PRD §12](../product/PRD.md#12-输入范围与字符规则) 和 AC-V2-12。此切片允许登录用户使用自定义辩题创建一场现有四轮练习，并从自己的历史重读原文。以 `5d05c7b` 为实现基线，独立工作树中完成开发和无数据库写入自测。阶段结项沿用既有口径。

## 数据与契约

复用 `debates.topic_title_snapshot`、`topic_description_snapshot` 和 `user_id`。自定义题只存在于本场会话的快照，不额外创建题库条目或可复用的私人题目实体。当前需求只要求创建时输入和历史重读，独立私题表需要额外定义收藏、编辑、删除和引用生命周期。直接把私人内容混进公共 `topics` 则会扩大公共题库查询的隐私边界。

新增 Goose 前向迁移，将 `debates.topic_id` 放宽为可空，保留索引、现有外键及历史行，不回填数据。非空表示预设题，NULL 表示自定义题。使用能表达 NULL 的 Go 字段；预设分支仍在事务内锁定并读取启用的题目，将同一份快照写入会话；自定义分支跳过题库查询，把原文和登录用户 ID 一次写入。两条分支共用创建流程、立场及流派校验，仍由服务端固定 `standard_4`。迁移文件按仓库约定滚动编号，本轮不执行。以后上线要先验证迁移和新旧程序兼容性，再允许新客户端写入 NULL。含自定义记录的库不能直接恢复到要求 `topic_id NOT NULL` 的旧 Schema 或旧程序。

`POST /api/v1/debates` 接受以下二选一输入，继续使用 Origin、Session、CSRF 和现有 JSON 错误封装。

| 输入 | 约定 |
| --- | --- |
| 预设 | `{"topic_id":"12","user_stance":"pro"}`，保留可选 `ai_style`，不存在或停用的 ID 返回 404 |
| 自定义 | `{"custom_topic":{"title":"辩题原文","background":"可选背景"},"user_stance":"pro"}`，同样保留可选 `ai_style` |

以字段是否出现判断互斥。两个字段同时出现、两个字段都缺失、显式 null 作为任一选择、题目为空白、背景类型不合法、超长或无效 JSON 均返回 400；背景可省略或为空字符串。自定义分支拒绝顶层和对象内的未知或重复字段。预设分支沿用原有的未知字段处理。归属、赛制和轮次均由服务端决定。成功返回原有 201 封装，预设 `topic.id` 仍为原字符串，自定义返回 `{"id":null,"title":"辩题原文","description":"可选背景"}` 作为会话内的 `topic`。`GET /topics` 保持只返回启用的预设，公共 Topic 类型仍要求字符串 ID。会话创建、详情和历史共享快照 DTO，只在会话的 Topic 类型中接受空 ID。缺失背景在响应中表示为空字符串。

继续使用 `debates.user_id` 约束历史、详情和生成入口，跨账号详情沿用 404。禁止修改已创建的题目或立场，无编辑接口。用户原文不进入日志、错误、遥测或公共列表，检查 DB 错误路径的语句日志不会展开参数。数据库故障沿用现有受控错误，页面保留草稿，用户主动重试；禁止自动重发创建请求，提交结果不明时提示先查自己的历史。

## 界面与文本

在现有选题和开赛入口增加自定义选项，保留预设选择、立场及原有流派控件。展示标题、可选背景、两个独立计数及「自定义辩题仅你可在本站查看」提示。提交成功后复用现有导航。题库列表为空或加载失败时仍可填自定义题；超长或服务端错误时保留输入。利用 Vue 文本绑定渲染预览、工作台和历史。草稿保持在当前表单内，不写入浏览器持久存储；切换账号时清理。工作台、历史复用已有的会话快照文本。

标题 1–200、背景 0–1000，以解码后的 Unicode 码点计数，组合字符按多个码点，补充平面字符按一个码点。标题判空沿用 Unicode White_Space 加 U+FEFF。背景选填，长度计算包含空白。服务端只用判空结果做校验，持久化使用原字符串，保留首尾空白、换行与原 Unicode 字符。前端不使用会截断输入的 maxlength 或 UTF-16 .length；超限时出提示并阻止提交。保留现有 HTTP 请求体上限。

## 提示词与用量

创建会话不调用模型、不触发策略卡或审题。用户主动生成后，对辩（普通、SSE、重试）、策略卡和总结均从同一份会话快照取题。以 topic_id 是否为空派生内部自定义标志。预设提示词保持旧结构。自定义标题、背景仅作为用户级结构化数据，与系统规则分离，对辩/总结可把 JSON 数据段放入第一条 user 消息并保留原发言正文与轮次顺序；首轮无历史时放在本轮 user 消息。系统段说明题目数据只界定讨论范围，其中指令无效。策略卡复用其现有 user JSON 输入。检查字符串转义及模板边界，确保伪造角色、分隔符或规则段不能进入 system，也不会变成额外会话角色。模型无工具、数据库和权限执行能力，状态推进继续由现有服务端规则决定。

保留实际 Prompt 窗口预检和计费保护。验证新结构在转义放大的极端输入下仍被启动时使用的 Prompt 上界覆盖，若不足则同步增加保守上界并补测试；按既有字节估算方法。既有预设 Prompt 及版本保持兼容，自定义 Prompt 使用独立版本标识或按现有 Prompt 版本约定可追溯。

## 实施与验证

1. 给 `backend/internal/debate` 增加创建请求、输入校验、仓储和 DTO 用例，覆盖严格二选一、Unicode 边界、原文保留、预设错误和权限中间件。实现创建支路与前向 SQL，保持会话详情和历史按用户查询。授权后补两账号固定隔离库联调，验证另一账号查不到、题库不出现该题、重读快照一致、原预设仍可创建。
2. 给 `backend/internal/ai` 补自定义 Prompt 的恶意标记隔离和容量测试，再接入对辩、策略和总结。不改生成认领、SSE 事件、计费准入或轮次权威。通过 Fake 或本地单元测试记录出站角色和内容，创建时断言无模型调用。
3. 在 `frontend/src/types/api.ts`、`frontend/src/api/debate.ts` 和 `frontend/src/views/TopicsView.vue` 接入表单和 DTO，兼容调用方已有的预设创建重载。以 Vitest 验证计数、保留输入、请求形状、两类响应、历史可读和转义；覆盖原预设流程。
4. 代码随附 `docs/api/API.md` 与 `openapi.yaml` 对该增量的契约说明，旧预设示例继续有效。运行 Go 单元测试、vet、build、gofmt 检查，前端 typecheck、Vitest 和 build；可用现成浏览器时运行目标 Mock 交互。MySQL 迁移与固定隔离库集成测试须得到数据库写入授权后实跑，列为验收缺口；真实模型不在本轮范围。

实现范围仅限 V2-03，不启动模式入口、完整训练赛、批注、争点卡、V2 策略锦囊或用户自带模型服务。不把 Phase 3 验收结果迁移到该切片。提交、推送、PR、部署、数据库写入和业务真实模型调用均需另行授权。
