# V2 页面设计模块索引与写作约定

> 这是 [V2 页面设计与交互细化](../PRD_V2_UI_DESIGN.md) 的模块目录。总览页只保留定位、页面清单、演示图索引与模块导航；每个页面的线框、字段、状态与恢复写在本目录下各自的文件里，方便并行维护。

状态：**页面与交互细化草案，随 V2 需求补充增量维护；未实现、未验收、未获开发阶段授权。**

## 1. 为什么拆成模块

- 一个页面一个文件，改动集中在单个文件，多个任务可以并行写不同模块而不互相覆盖。
- 总览页固定，页面细节下沉；读者按“我要看哪一页”进入，不需要通读全文。
- 每个模块顶部写明适用的 PRD 章节、AC 和实现状态，避免把目标态当成已交付。

## 3. 标记约定（逐条随文标注，不得省略）

| 标记 | 含义 | 谁能改变 |
| --- | --- | --- |
| `[已确认]` | 来自 [PRD V2](../PRD.md) 已确认行为（Q1–Q52），或负责人明确答复的事项 | 只能由负责人新决策改变 |
| `[已实现]` | 已有代码切片交付并签收，注明切片编号与日期；仍按 PRD 为准 | 负责人或后续变更 |
| `[补充草案]` | 基于已确认方向新增的界面与规格草案，**待负责人审阅，不是已签收** | 负责人审阅后改为 `[已确认]` |
| `[设计建议]` | 为实现已确认行为提出的界面做法，未经负责人确认 | 负责人或设计评审可改 |
| `[待决]` | 产品取舍或技术方案未定，界面不得先按某一方案写死 | 负责人确认或技术评估结论 |

- 本文不是产品事实源：产品行为、边界与 AC 以 [PRD V2](../PRD.md) 为唯一事实源，冲突时以 PRD 为准并修正本文。
- 不把 `[设计建议]` 或 `[补充草案]` 写成用户批准，也不把 `[待决]` 写成已定。`[待决]` 一律给恢复动作或空态说明，不给结论。
- 不锁定色值、字体、组件库与高保真稿；色值与对比度按 [PRD §5.3](../PRD.md#53-标记形式颜色--线型--文字标签q41) 留待设计验证。

其余页面（训练赛阶段、争点卡、异议、局部重练、复盘、PDF、设置）仍为**目标态**，任何一项都不代表已存在。

## 5. 模块写作模板

每个模块按下面顺序写，缺项要说明原因，不要留空标题：

1. 模块标题 + 一行说明（所属页面、对应 PRD 章节、实现状态）。
2. 适用规格表：PRD 章节 / AC-V2 编号 / 实现状态。
3. 演示图引用 + 一句话说明这张图展示什么。
4. 文字线框（`text` 代码块），表达布局与关键控件，不用 ASCII 追求像素级一致。
5. 字段与操作表；状态与恢复表（触发 / 界面表现 / 允许动作 / 禁止）。
6. 不做什么、`[待决]` 项及其归属。
7. 与其他模块的引用链接。

## 6. 约定

- 中文、LF 行尾、无 BOM、不使用表情符号分隔线；表格保持可读，不为了排版删信息。
- 路径链接使用相对路径；跨模块引用写模块文件名，跨文档引用写 `../` 相对路径。
- 新增事实必须有来源（PRD 章节、决策记录、验收记录或负责人答复），没有来源就标 `[设计建议]` 或 `[待决]`。
- 代码、命令、路径、ID 保持原样；示例数据不得使用真实 Key、口令、学号或私人联系方式。
