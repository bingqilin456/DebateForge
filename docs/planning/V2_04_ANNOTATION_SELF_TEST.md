## 6. 设计偏离与实现取舍

1. **批注资格标志与正式完成解耦。** 设计文档要求在「同一条完成 UPDATE」中设置 `annotation_eligible`。实现遵守了这一点（`Repository.Complete` 的同一 `Updates` 内写该列），但为把「是否允许批注」传进完成路径，`Store.Complete` 增加了一个 `eligible bool` 参数。它只影响该列的写入，不改变轮次状态、完成轮数或会话状态的任何计算。
2. **手动补做上限改为认领期判定。** 设计文档写「手动重试最多一次」。实现没有在输入层拒绝 `expected_attempt_version>1`，而是在认领时按「首次 v1、补做 v2，此后保持失败」判定。这样已成功批次的重放仍能返回 `200` 与已存结果，而不是先被输入校验拒成 `400`。
3. **未启用切片时补做入口返回 `400`。** 设计文档只说「默认关闭」。实现选择在关闭时对该 POST 返回受控 `invalid_request`、且不写批次行，读取仍返回空列表；理由是不在关闭状态下暴露一个会写库但永不成功的入口。
4. **`APP_ENV` 只接受 `test`。** 设计文档写「固定测试环境」。实现据此拒绝 `dev`/`demo`，避免在日常联调环境里静默产生批注批次与额外模型调用。
5. **`Intl.Segmenter` 缺失时的降级更保守。** 追加要求是「未提供此 API 时安全降级」。实现把「无法判定」与「确认在内部」区分开：缺 API 时只有整条原文这类安全端点可高亮，其余内部区间一律显示待核对，而不是猜测边界可用。
6. **前端未新增任何依赖。** 字素分段使用浏览器原生 `Intl.Segmenter`，没有引入第三方分段库或手写 Unicode 表。
