# T16 备份恢复与基本运维执行计划

本文是执行计划，不是验收记录。进度以 TASKS 为准。

以 [TASKS](../docs/planning/TASKS.md) 中的 T16 为范围，沿用 [T07 部署说明](README.md)；不做 T17 正式部署，不改业务契约或数据库迁移。先完成部署前演练，再在目标部署具备后补现场证据。

## 1. 两条可独立执行的隔离演练

| 工作线 | 交付范围 | 验证与停止条件 |
|---|---|---|
| DSH A：备份与恢复 | `deploy/ops/backup/`：最小备份与恢复工具、使用说明和脱敏演练记录。备份使用加密、可校验的快照；接收端保留密文，恢复密钥与备份分开。 | 用独立 Compose 项目、容器卷和合成辩论数据；备份后在另一独立库恢复，核对版本与本人历史可读。损坏文件、错误密钥、非空目标和源目标重合必须拒绝。模拟异机不能当作真实异机证据。 |
| DSH B：告警、续期与应用回退 | `deploy/ops/health/`：最小检查工具、使用说明和脱敏演练记录，复用已有健康端点和 T07 回退方式。 | 验证应用不可用、数据库不可用、备份失败或过期都能告警，并验证恢复通知；拒绝把 HTML 200 当健康。用隔离证书验证更换后实际握手、续期失败告警；验证只切换应用镜像，不替换数据卷，Schema 不兼容时不回退。 |

Codex 从同一基线建立两个互不包含的 worktree；测试不得共享端口、Compose 项目、网络、卷、数据库或收件目标。可用临时收件点证明本地投递，不宣称现场通知已到达。如果资源不能隔离就串行。Worker 不提交、不触碰生产资源、不调用产品真实模型。先各自自测，释放写入 claim 后由 Codex 核对代码与证据、整合并补验；`deploy/README.md`、`TASKS` 和汇总证据由 Codex 统一更新。

## 2. 部署前闸门

- 记录基线 SHA、MySQL 与迁移版本、备份生成/校验时间、独立恢复目标、预计回退镜像标识及 Schema 兼容核对。任何环境或版本不明时先停在核对，不执行写入。
- RPO（最多丢了多久的数据）：以模拟故障时点减去恢复后实际可读的最后一条预置标记时间；同时记录备份恢复点及其时区。RTO（多久恢复可用）：从宣布启动恢复到应用健康且能读到预期历史。按 [A08](../docs/decisions/DECISIONS.md) 的 RPO 24 小时、RTO 2 小时目标对照，记录 UTC 起止、计算口径与实测值；本地实验不能证明生产达标。
- 为每项记录环境、命令或步骤、预期、实际结果、证据位置。没有跑过的检查标为未执行；不提交密钥、备份内容、账户或辩论正文。

## 3. 目标部署后补证据

按 [TASKS](../docs/planning/TASKS.md) 的顺序执行：先通过部署前闸门，目标部署后才补现场证据，T16 验收后再做 T17 最终回归。

- 确认异机密文可取回并校验、经独立库实证可恢复；不在生产库做恢复试验。
- 按实际访问标识核对证书更换、续期钩子与新连接握手。私有 IP 模式使用含 IP SAN 的私有 CA 证书，经 SSH 隧道验证。公网模式按获准的域名或公网 IP 及对应的 ACME 方式取证。核对监控的收件人和到达记录，以及证书、应用、数据库、备份故障和恢复路径。
- 核对已批准的旧镜像与当前 Schema 相容，记录应用回退前后镜像、同一数据卷、健康及历史可读。不存在可用旧镜像时登记缺口，不把停止服务当成成功回退。
- 单列 [T07-COST-01](../docs/planning/TASKS.md#t07-cost-01-供应商硬预算缺失)：依据 ADR-022，核对充值余额兜底、全站次数与 Token 预算跨重启、自动熔断和紧急停用跨重启；真实公网试运行前还要确认没有隐式自动重试。告警、在途和对账按风险与授权范围验证。记录目标账户及 Key 的脱敏标识和已批准的额度，不记录秘密。实际环境、操作和费用边界未明确时只核对方案，不触发付费调用、不开放公网、不改生产资源。
