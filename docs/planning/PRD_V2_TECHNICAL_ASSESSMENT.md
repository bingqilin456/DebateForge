# 思弈阁 V2 技术评估与开发规划

日期：2026-11-17。状态：**评估草案，未获开发授权**。本文为 [PRD V2](../product/PRD.md) 提供粗略的相对成本、技术风险、真实差异化程度、依赖顺序与后续阶段建议，并集中登记待评估项。

**全文数字均为研究估算，不是排期、报价或成本承诺。** 本文不批准编码、迁移、真实模型调用、数据库写入、部署或阶段结项；也不构成对 [V1 Phase 3](../planning/TASKS.md#phase-3赛制流式破局亮点与质量攻坚) 任何任务的重新定级。

## 1. 约束前提

1. **不沿用旧 PRD 的非目标否决新需求**。V1 的「明确不做」只用于识别复用资产与迁移成本。
2. **不引入新基础设施**：仍为单 Go 实例、单 MySQL、进程内并发控制；不引入 Redis、队列、向量库、微服务或复杂 Agent 编排。
3. **复用 V1 已有机制**：所有权校验、`client_request_id` 幂等、`attempt_version`、90 秒租约、并发配额、短事务、事务外模型调用、提交后 `done`。
4. **产品 V2 与 Phase 3 的 `phase3-summary-v2` 分名处理**，不共享字段与取值，见 [ADR-027](../decisions/DECISIONS.md#adr-027-v2-需求基线与版本边界) 的「决定二」。
5. **任何真实模型调用、费用与额度调整都须单独授权**；本文只指出不匹配，不声称已调整。

| --- | --- | --- | --- | --- | --- |

| V2-03 | 自定义辩题（私有） | 能用自己关心的题目练习 | M | 中：`topic_id` 外键与快照模型改造、私有性、不可信主题隔离 | 低：属基础能力 |

| V2-07 | 回应定位与定位失败降级 | 点击卡片即回到双方原句 | M | 中：锚点失效、无法唯一定位时的降级必须可见不猜测 | 中—高：与 V2-04 共用锚点资产 |

| V2-09 | 三档训练强度 | 同一题给不同水平的人不同侧重点 | M | 中：**行为差异难验证**，易只做出长度/措辞差别 | 中：档位常见，真差异要靠质量验证 |
| V2-10 | 四维 1–4 档行为参考 + 观察不足 | 有依据、可跳转的分维反馈，而非一个分数 | **L** | **高**：无依据不得赋档、观察不足判定、原文依据可核 | **中—高**：拒绝总分/档级严守行为标准比打分更难做对 |
| V2-11 | 单场雷达图与原文联动 | 一眼看到哪一维弱，并能跳到原文 | M | 中：缺项展示（不能按 0 画）、点击联动 | 中 |
| V2-12 | 赛前策略锦囊 | 开赛前有破题方向，不代写 | S–M | 低—中：显式调用、失败不阻塞、不越界成整段论稿 | 低—中 |
| V2-13 | 赛后复盘（不判胜负） | 集中、可执行的改进建议 | M | 中：四维与争点、建议的一致性 | 中 |
| V2-14 | PDF 战报（零新增调用） | 可带走、可存档的单场报告 | M | 中：中文字体、分页、图表清晰度；须证明零模型调用 | 低—中 |

| V2-16 | 生成失败、恢复与只补失败部分 | 失败不毁掉已有成果 | M–L | **高**：部分重试不整场重生成、不覆盖成功结果与人工编辑 | 中—高 |

**合计判断**：V2-02、V2-04、V2-06、V2-08、V2-10、V2-16 是六个高成本项，也是差异化的主要来源；其余为基础或低成本项。切片之间有共享资产（锚点、卡片、状态机），**不能简单相加**。

## 3. 真实差异化程度的分级口径

- **高**：需要平台维护跨请求的持久状态、稳定定位或不可逆的历史隔离，通用对话难以替代。
- **中**：主要价值来自交互组织与规则约束，模型本身也能生成类似内容。
- **低**：属基础能力或通行做法。

本文不宣称任何能力「全球唯一」或「通用 LLM 无法生成」；差异化指**工程责任与用户体验路径**，不指模型能力。

## 4. 依赖关系：硬依赖与建议集成顺序

本节区分两类关系，避免把建议顺序写成必经依赖。

**A. 硬依赖**（技术上不先做就无法正确实现，仅此四条）

| 硬依赖 | 理由 |
| --- | --- |
| V2-02 阶段与可变回合 → 所有对「当前阶段/回合数」做判断的功能 | 阶段语义是 V2 会话的基础事实；阶段未定则任何依赖阶段的展示都会返工。**不构成**「必须先做完 V2-02 才能动别的」——V2-02 与下列功能可以并行设计，只是其落地要等到阶段契约稳定 |
| V2-04 锚点层 → V2-06 争点卡、V2-07 回应定位 | 后两者复用同一套文本锚点；先做卡片会出现两套定位逻辑 |
| V2-10 四维 → V2-11 雷达图 | 雷达图是四维档级的展示形态，没有档级定义就无处可画 |
| V2-13 复盘 → V2-14 PDF 战报 | PDF 复用已保存的复盘结果，且**不得**新增模型调用 |

**B. 建议集成顺序**（推荐，但**不是**硬依赖；可独立准备或提前落地）

| 建议顺序 | 内容 | 为什么只是建议 |
| --- | --- | --- |
| 1 | V2-02 阶段与可变回合、V2-01 模式入口、V2-15 历史与失败态 | 三者结合时体验最完整；但 V2-15 的历史三态独立于阶段实现即可成立 |
| 2 | V2-03 自定义辩题 | 只依赖格式校验与私有快照，**不需要**阶段模型，可独立先行 |
| 3 | V2-04 原文批注与锚点、V2-16 只补失败部分的重试 | 批注是多数特色的锚点来源；V2-16 的「只补失败部分」与锚点强相关，宜同期设计。二者均可在阶段契约稳定前独立准备 |
| 4 | V2-06 争点卡、V2-07 定位降级、V2-05 异议 | 依赖锚点层（硬）；彼此之间可并行 |
| 5 | V2-08 局部重练、V2-09 三档、V2-10 四维档级、V2-11 雷达图 | 参见下方两条澄清 |
| 6 | V2-13 复盘、V2-12 策略锦囊、V2-14 PDF 战报 | 复盘与 PDF 有硬依赖；V2-12 策略锦囊只依赖开赛前的会话状态，**可独立提前** |
| 需求池 | 流派、双 AI 观摩、演化树、联网核查、裁判评分 | 另行评估，不承诺实现 |

**两条须澄清、此前被写成过强依赖的关系**

- **V2-08 局部重练不依赖争点卡**：重练有两条入口——从批注进入，或**主动选中自己的一段原文**进入（Q39）。后者不需要任何批注或争点卡即可成立，因此局部重练不构成「必须先有争点卡」。
- **V2-10 四维不依赖局部重练**：四维是对本场表现的赛后评估，数据来自已有发言与复盘；重练是赛后的额外练习，不是四维的输入。二者可独立实现，同期做只是体验更连贯。

**建议批次（供排期讨论，非承诺）**

| 建议批次 | 内容 |
| --- | --- |
| 批次 A | V2-02、V2-01、V2-15；V2-03 与 V2-09 的行为样本可同期独立准备 |
| 批次 B | V2-04、V2-16；V2-12 策略锦囊可同期独立交付 |
| 批次 C | V2-06、V2-07、V2-05 |
| 批次 D | V2-08（可先按主动选段入口落地）、V2-10、V2-11 |
| 批次 E | V2-13、V2-14 |
| 需求池 | 流派、双 AI 观摩、演化树、联网核查、裁判评分 |

批次间为**建议集成顺序**，允许在依赖满足时调整；唯一不可颠倒的是上表的四条硬依赖。批次内「V2-09 三档」的验证样本与「V2-03 自定义题」均不需要等待前一批次完成。

**明确不做的安排**：不预先给出 A/B 具体人日承诺；不在本文确认任何任务的负责人；不因本文而改变 [一功能一负责人](../planning/PLAN.md#现行功能分工原则) 原则。

## 6. 已知额度不匹配

**这是已确认的不匹配事实，不是已解决的问题。**

- 现有配置：每用户**每天最多 20 次生成尝试**（失败尝试也计入），单用户并发 1、全局并发 2。
- 一场**最长**训练赛至少需要：立论 1 + 驳立论 1 + 自由辩 10 + 结辩 1 = **13 次对手生成**，复盘另需 1 次。
- 若批注按「每次 AI 发言后 0–3 条」独立调用，一场满回合训练赛最多可再加 13 次以上；争点卡按每个完整回合更新亦会增加。
- 结论：**现有 20 次/日的额度与「一场最长训练赛 + 多次分析」不匹配**，用户可能在半场就被额度挡住。

**建议的评估方向**（均为待评估，未实施）：

1. 以「完成一场的总预算」而非「单次调用」重新定义额度，至少覆盖一场满回合训练赛及其必要分析。
2. 区分**正式发言**与**辅助分析**的额度池，保证分析永不挤占用户完成比赛的机会。
3. 明确分析类调用是否计入每日额度、失败是否计入、重试是否只补失败部分（与 V2-16 一致）。
4. 评估把「批注 + 争点卡」合并为更少的调用次数，以调用组织换额度。
5. 任何额度调整、费用上限与真实调用授权**必须单独取得负责人批准**；本文不声称已调整。

## 7. 风险登记

| 风险 | 影响 | 缓解方向 |
| --- | --- | --- |
| 状态机重建破坏 V1 历史可读性 | 既有用户历史无法继续或展示错误 | 阶段模型对旧数据只读兼容，迁移前先定映射；TE-13 |
| 锚点定位不稳导致错误高亮 | 错误归因，比没有批注更糟 | 无法唯一定位则显示「待核对」，绝不猜测 |
| 争点卡更新覆盖人工编辑 | 用户劳动被丢弃 | 人工编辑优先，冲突可见；TE-11 |
| 分析调用挤压正式发言 | 辩论被辅助功能拖慢 | 分池与优先级；TE-12 |
| 三档/档级只有形式差异 | 特色落空，验收不可信 | 先定验证方法再实现；TE-05、TE-06 |
| 费用与额度不足 | 用户中途被挡、体验断裂 | 重定额度模型；§6 |
| 文档命名混淆（三类 V2） | 误读实现状态与替代关系 | [ADR-027 决定二](../decisions/DECISIONS.md#adr-027-v2-需求基线与版本边界)；各处显式分名 |
| 范围膨胀 | 一次重构变成无限扩张 | 未确认的小功能不纳入；见 [PRD V2 §13](../product/PRD.md#13-暂缓项与后续需求池) |
