# 03 局部重练

范围为 V2-08，对应 [PRD §5.7](../../product/PRD.md#57-局部重练q16q28q32q39)、[完赛复盘](../../product/ui/04-review.md)及 AC-V2-17、26。

## 设计与边界

- 首条可独立实现的路径是完赛后选中本人已保存发言的一段原文，可选填本次改进目标。服务端按会话所有权、完赛状态、发言方和原文匹配验证；未完赛、AI 发言和其他会话原文拒绝进入。
- 面板先展示原句、已有批注（存在时）与练习提示。打开面板不触发生成。用户提交 1–2000 字改写后生成对照反馈，说明原问题是否改善、理由和可能的新问题。给局部提示，保留用户自己的写法。
- 每次重练保存独立版本，绑定同一原文，可回看改写、反馈与失败状态。失败后按已知版本显式恢复，避免网络重发造成重复版本或调用。重练表与正式比赛发言、后续步骤隔离。
- 先用四轮完赛和无批注夹具交付。后续复用标注入口，仅在引用指向本人发言时提供快捷跳转。批注缺失、定位失败或复盘失败时，仍可从已保存的本人发言主动选段。
- 记录模型和重试策略按 TE-01、TE-10、TE-12 评估，额度从服务端读取。失败时保留本次输入和其他版本。

## 执行与验收

1. 定义选段与重练版本的动作表，并用固定夹具验证是否完赛、是否本人、是否本场原文。
2. 用 Fake 验证用户提交后才生成，输入空白、边界字数、重复提交、生成失败及恢复、多版本刷新不丢失。对比原会话发言、阶段及复盘结果，用例中确认它们未被改写。
3. 用 Mock 在完赛页验证无批注仍可重练、有批注时能带入同一原句、失败保留改写。完赛页公共入口与 04 由整合负责人一次接线。

### 1. 选段与版本动作表

| 动作 | 入口 | 服务端校验 | 写库影响 | 失败语义 |
| --- | --- | --- | --- | --- |
| 读取历史 | 完赛页重练面板加载 | 会话归属；完赛状态 | 只读 `debate_repractice_versions` | 越权/不存在 404；未完赛 409 |
| 主动选段 | 本人发言选中原文 → 选句重练 | 前端按码点换算，提交时服务端再复核 | 不发请求 | 空白/跨消息选区只给本地提示 |
| 提交改写 | 面板「提交改写，查看反馈」 | owner、完赛、`message_id`+user 方、`[start_cp,end_cp)` 与原文逐字相等 | 新增独立版本行；不改 `messages`/`debates`/`debate_reviews` | 保存失败原样报错且不调模型；生成失败落 `failed` 并保留改写 |
| 显式重试 | 失败版本「重试这次反馈」 | 版本归属、`status=failed`、`attempt_version` 匹配 | 同一行 attempt+1，不新增版本 | 版本不匹配只读回当前状态，不自动换版本重发 |
| 回看历史 | 面板历史版本区 | 会话归属 | 只读 | 刷新后从服务端恢复 |
| 恢复到编辑区 | 历史版本「恢复到编辑区」 | 纯前端填充 | 不写库、不覆盖既有版本 | 再次提交才新建版本，并带 `restored_from` |
| 复盘/争点引用入口 | 复盘四维「去重练」；争点卡预览点击已核对的用户原文 | 引用坐标先在前端逐字复核，服务端仍独立校验；AI 引用不提供重练选段 | 不发请求（只填表） | 坐标不可核对时只带改进提示，不伪造原句 |

### 2. Fake 与规则层验证（Go）

`backend/internal/debate/repractice_test.go`、`repractice_http_test.go`、`repractice_memory_test.go`：

- 空选段、坐标与原文不符、AI 原文、未完成轮次、未完赛会话（409）、他人会话（404）均被拒绝；
- `甲😀乙`/补充平面字符按 Unicode 码点半开区间切片，UTF-16 下标混用会失败；2000 码点接受、2001 拒绝；
- 同 `client_request_id` 重放幂等且不重复调用模型；同编号不同内容拒绝；新编号产生独立版本；
- 生成失败保留改写与失败版本，`Retry` 只推进同一版本（attempt=2），已完成版本再次重试不重生成；
- 保存失败时错误原样返回且生成器调用次数为 0（先保存后生成）；
- 反馈写回失败时，仍处于生成中的版本可保存为失败并重试同一版；
- 关闭能力时不访问新表（`available=false`，写入口 400），越权/不存在仍 404；
- 内存夹具断言正式原文、轮次与会话状态在重练全程未被改写。

`backend/internal/ai/repractice_test.go`：Prompt 把用户原文只放 user 数据段；结构校验拒绝未知/缺失/重复字段、非布尔 `improved`、空 `reason`、超长文本；Fake 脚本化失败与取消上下文均返回受控错误。

### 3. 完赛页 Mock 浏览器验证（Playwright，无后端/无模型）

`frontend/e2e/repractice-mock.spec.ts`（`npm run test:e2e:repractice`，独立端口 5175，用例内 Mock 全部响应）：

- 无批注也能主动选段进入重练；选段本身不产生任何请求；
- 失败提交保留改写与失败版本；刷新后从服务端恢复；按 `expected_attempt_version=1` 显式重试同一版本；
- 反馈只出现「是否改善 / 理由 / 可能的新问题」，没有评分文案与整段范文；
- 历史版本恢复到编辑区不创建版本；继续提交才新建版本并带 `restored_from`，原版本不被覆盖；
- 复盘四维入口复用同一入口，带入原句与改进提示且不触发生成；
- 全流程仅写 repractice 接口，没有会话/轮次写请求，原文保持原样；
- 能力关闭时整块重练区与入口隐藏。

`frontend/e2e/review-mock.spec.ts` 同步更新了旧断言（重练已从「待整合」变为正式入口）。

`IssueCardPanel` 的已核对用户引用点击仍触发原文定位，并在独立第一批预览内把同一消息与码点区间带入重练表单；AI 引用仅定位。此接线复用现有引用投影和回调，不依赖 V2-02 阶段模型/API。
