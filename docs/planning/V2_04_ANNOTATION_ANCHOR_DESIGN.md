# V2-04 原文批注与锚点设计及实施计划

日期 2026-11-18。基线为 V2-03 的 `8a9cfd4`。本轮在独立工作树开发现有四轮练习的原文批注，用 Fake 和隔离测试验证。适用规格为 [PRD §5](../product/PRD.md#5-特色一原文批注与局部重练)、[分析失败与重试](../product/PRD.md#103-分析失败与重试q33)、AC-V2-13～16 及 [页面 P6c](../product/ui/03-workspace.md#8-批注p6c)。完整训练赛接入随 V2-02，异议、争点卡、回应定位、局部重练、通用分析重试和复盘生成各自独立交付。

第三场真实复验发现的引用生成问题和后续设计见 [引用生成改造方案](V2_04_ANNOTATION_REFERENCE_REFACTOR.md)，提案待评审。

## 设计选择

- 用已提交消息 ID 确定身份，以原文的 Unicode 码点半开区间定位，保存逐字引用用于回读校验。纯字符串搜索无法可靠区分重复句。使用 UTF-16 或字节偏移会让另一端依赖实现细节。
- 批注单独持久化，生成在正式轮次提交后做。仅为本次允许生成的轮次在同一条完成 UPDATE 中设置 `annotation_eligible`，默认 false，旧行保持原状。此字段只标识批注资格。写批注记录和执行分析均在正式轮次事务之外，避免分析失败影响提交。生成不改变轮次、会话完成或总结状态；普通和流式入口都使用同一个完成出口。
- 当前进程仅提供 Fake 生成实现，生成由显式本地测试配置开启，仅允许固定测试环境、`AI_MODE=fake`。默认关闭。采用一个非阻塞、无积压的分析槽，忙时留下可手动补做的状态，不占用正式发言或总结的 Gate。批注真实供应商接入前另定 TE-01/02/12，明确模型、费用、总并发、前台优先与限额；现有 Demo 的真实模型额度不扩充。Fake 的结果用于验行为，不验证输出质量。

## 锚点契约

参考 [W3C Web Annotation Data Model](https://www.w3.org/TR/annotation-model/#selectors) 的原文引用和码点位置，以及 [Hypothesis](https://github.com/hypothesis/client/blob/main/src/annotator/anchoring/html.ts) 对位置命中的原文复核。思弈阁按不可编辑的已提交消息定位，精确匹配不唯一时显示待核对。若后续确需提高重复原句的定位率，优先评估 W3C 的精确前后文消歧；仍有歧义时保留待核对。前端使用标准 [Intl.Segmenter](https://tc39.es/ecma402/#segmenter-objects) 检查可见字素边界，避免自行维护 Unicode 分段规则。

| 字段 | 含义 |
| --- | --- |
| `message_id` | 服务端已知的、属于当前会话的正式消息 ID，JSON 为字符串 |
| `start_cp` / `end_cp` | 从 0 开始的 Unicode 码点半开区间，按原始消息文本计数 |
| `quote` | 对应的连续原文，逐字符精确相等；禁止 trim、归一化、大小写折叠和替换标点 |

分析器以 `message_id + quote` 提交候选，可带 `start_cp` 消歧。服务端提供可复用的纯解析函数，针对已经授权并加载的单条消息定位。引用在该消息中只有一次精确匹配时，由服务端重算位置。引用重复时仅采用能逐字复核的提示偏移，仍有歧义则只显示“原文待核对”。跨消息、空引用、全空白、错误 ID、未来轮消息及非法字符均拒绝定位。读取旧批注时，服务端可在触发轮或更早的已提交消息中按唯一原句重算坐标，只修正读取结果。无权消息或非法内容不得返回引用。回读时前端以 `Array.from(content)` 再校验；不要按 JS 字符串 UTF-16 下标切片。组合字符和 ZWJ 保留原码点，切中可见字素导致破碎显示时降级为待核对，从原句入口读取未经修改的完整原文。

批注条目含 `category`、`label`、`reason`、`improvement` 和锚点（或待核对状态）。类别固定为 `strength`、`possible_logic_gap`、`insufficient_support`、`unclear_scope`。标签、理由、方向和引用用非空纯文本，长度上限分别 40、300、300、300 码点。每次结果合计 0–3 条，允许空集合，同范围多类别允许，完全重复条目拒绝。理由和方向使用训练用语；逻辑问题表述为可能的推理缺口，缺来源不判事实错误，优点写为何有效，不声称检索或核实。Fake 固定样例体现这些规则。未来供应商需走同一结果校验，并另验语义质量。

## 请求、存储和恢复

- 新增前向迁移（从实施基线核号，`00014` 已使用）。`turn_annotations` 以触发 `turn_id` 唯一，记录 `status`、`attempt_version`、`lease_expires_at`、受控 `error_code`、`content_json` 和 UTC 时间；复用现有外键删除策略。通过 `debates → debate_turns → messages` 验归属。无需另建原文副本、全局锚点表或训练状态事实源。成功结果整体原子保存，包括空数组。
- 用同一个后端服务在正式 `Complete` 成功后尝试分析。单槽非阻塞，忙则保留资格，读取时表现为待分析，允许手动补做。分析控制在已获许可的 Fake 测试模式内。异步工作有固定期限（建议最长 10 秒）、限定的并发和异常清理；不继承浏览器断线取消。进程退出和启动不自动补跑。服务重启后可读既有结果，过期生成视为失败，下一次限定范围的手动认领可恢复。
- 绑定触发轮及提交时的消息集合。主输入为该轮新提交的双方原文，上轮或更早已完成原文只作关联背景，允许指向其引用但每次关联必须有本轮新内容的依据。输入仅取当前会话、触发轮及以前已提交消息；慢批注绝不能读到后轮并挂错。四轮流程一次有一对消息；未来 AI 先手时只评价新增发言。重放、查询、刷新不得自动补跑旧任务或重复扣费。
- `GET /api/v1/debates/{id}/annotations` 返回当前会话按触发轮排序的批次，字段含 `turn_id`（字符串）、`status`（`not_started/generating/completed/failed`）、`attempt_version`（未认领为 0）、`items` 和可选 `error_code`。只有已启用切片产生的合格轮次参与该读取；旧会话返回空列表。读取无模型调用、不写 DB。
- `POST /api/v1/debates/{id}/turns/{turn_id}/annotations/retry` 用现有认证、Origin、CSRF 和防刷前置，正文仅 `expected_attempt_version`。未启动用 0；仅允许补做未认领或按版本重试失败/过期批次，生成中回 202、已成功回已存结果、版本不符回 409 并查询。无权或会话不匹配按现有规则 404；非合格轮不启动。认领和结果更新均须按批次当前版本检查，旧响应不能覆盖新尝试；锁外执行分析，非成功只保存安全错误码。手动重试最多一次，成功批次始终保留。初次分析和重试共用同一 Fake 分析槽及认领逻辑。
- 读取当前会话和历史详情都只查询同一批注 API。前端只在可见会话有正在生成或新完成轮次时短期查询，查询有截止时间，页面切换清理定时器及过期响应；无自动 POST 或自动重试。关闭场中显示只改展示，不改服务端生成。已完赛后可看批注，包括总结失败时。

## 实施与核验

1. **锚点与结果解析。** 在后端独立的 `internal/debate` 锚点/批注文件中实现纯函数，沿用已有消息类型和严格校验惯例。先用表驱动用例覆盖中文、emoji、组合符、不同时出现的重复句、带偏移的重复句、越界、无权限或未来轮、空结果及四条拒绝。写保护与数据库查验在调用边界处理。保留 V2-06/07 后续可复用的输入输出，不提前创建其表或接口。
2. **持久化与生成。** 在 `backend/internal/debate` 写薄 Handler、Service 和 Repository，在现有 server 装配处启用明确的 Fake 能力。修改正式完成路径只限资格标志与提交成功后的非阻塞通知。新增迁移、记录 API/OpenAPI，已有响应字段和 SSE 事件保持兼容。验证正常完成、生成拒绝、超时、panic、并发重复、租约过期、旧版本写入与恢复；验证 JSON/SSE/显式重试只在提交成功后安排一次，安全测试覆盖会话越权、Origin/CSRF 和未提交消息。固定隔离 MySQL 仅在核验安全可用且无其他任务占用后做迁移和集成取证。
3. **前端体验。** 在实际工作台与历史详情公共展示路径复用批注组件，使用现有 `src/api` 和 `src/types`。桌面侧栏、移动端底部面板，解释默认折叠。淡绿底实线、橙色波浪线、淡蓝底虚线、紫色下划线都带文字标签。完全相同区间合并成一个入口；部分重叠按边界切分为无重叠文本段，重叠段展示一个入口并列出所有适用标签，不叠底色。标记与解释双向定位，键盘可达并保留返回焦点，用户与模型文本均转义。测试开关只控场中显示、零条、轻失败、手动补做、慢响应、旧历史、复盘失败仍可见及 Unicode 不错标。
4. **交付。** Go 单测、竞争专项测试、vet/build、迁移工具相关检查，前端 typecheck、Vitest、build 和关键浏览器 Mock。允许固定隔离库核验时补 MySQL/Fake 浏览器源到端记录，按实际成功项登记；未满足则明确缺口。提交变更清单、测试命令及结果、主要风险。业务真实模型、部署、生产数据和阶段结项不在本次实施授权内。

验收映射：AC-V2-13 对应步骤 1～3 的内容结构和原句，AC-V2-14 对应步骤 3 的颜色、线型、标签和展示行为，AC-V2-15 对应步骤 1～2 的批次及输入边界，AC-V2-16 对应步骤 2～3 的失败、延迟和继续发言。Fake 技术验收和真实输出质量分开记录。
